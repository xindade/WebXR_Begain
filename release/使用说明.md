# 双端使用说明（WebXR 直播）

> 本次更新：修复「推流端离线·PC 黑屏无日志」问题，新增日志区 + 游戏托管兜底 + 端口自动 fallback。

## 关键变化

**之前**：EXE 界面是纯黑的，中间显示「等待推流端连接…」，底部**没有日志区**，所以看不到任何协商过程——出问题只能猜。

**现在**：
1. **底部新增日志区**：实时打印 SSE 连接、peer-ready、offer/answer、ICE 状态、画面切换等所有关键事件。
2. **新增「游戏目录」配置**：EXE 自动探测 `E:\AI_Work\WebXR_Begain`（含 `index.html` 的项目根）。启用后，**头显浏览器直接打开 PC 地址即可出画面，完全绕开 APK 代理链**——这是最强诊断/兜底路径。
3. **端口自动 fallback**：默认 8443，被 http-server / nginx 占用时自动 +1，APK 通过 UDP 信标自动拿到实际端口。

## 两套使用路径

### 路径① · APK 路径（推荐 · 日常使用）
1. 电脑双击 **PC端-直播接收端-Setup.exe** → 看到顶部「本机地址」、底部日志区。
2. 头显点 **头显端-WebXR打气球.apk** → APK 弹出提示「正在搜索 PC…」→ 约 1~2 秒后显示「已连接 PC 接收端 192.168.x.x:8443」→ 自动跳转 PICO 浏览器进 VR。
3. PC 窗口出现画面，**底部日志区**应依次出现：`已注册为接收端，监听中…` → `推流端已上线` → `收到推流端 offer` → `已发出 answer` → `收到远端媒体流，开始显示画面 ✅`。

### 路径② · 直连路径（兜底 · 诊断）
如果路径① 长时间不出画面，**跳过 APK**，直接验证游戏 + 接收端：
1. PC 端 EXE 启动后，**确认顶栏右侧显示「✓ 已托管：E:\AI_Work\WebXR_Begain」**（若显示「未配置」，在游戏目录输入框填好后点「应用」并重启 EXE）。
2. 头显浏览器（PICO 浏览器 / Chrome）打开 `http://<电脑IP>:8443/?cast=1`，进游戏。
3. 头显进入 VR 后，PC 窗口应出画面。

**若路径② 出画面，路径① 不出**：问题在 APK 代理链（discovery / GameServer / 信令代理），不在游戏侧。
**若路径② 也不出**：问题在游戏侧（推流/WebRTC）或网络（P2P）。

## 排查速查（看底部日志区）

| 日志卡在哪 | 含义 | 怎么办 |
|---|---|---|
| 只有 `已注册为接收端，监听中…` | publisher 没连上信令 | 看头显：`?cast=1` 是否加；APK 端是否显示「已连接 PC」 |
| `推流端已上线，等待其发起 offer…` 但无 offer | 游戏侧推流没启动 | 头显在游戏菜单而非关卡内；或推流初始化失败（看头显 Toast） |
| `收到推流端 offer` → `已发出 answer` 但无媒体流 | WebRTC ICE 失败 | 关电脑防火墙 / 确认同网段 / 换 JPEG 兜底（`constants.js` 改 `CAST.TRANSPORT='jpeg'`） |
| `ICE failed：P2P 通道不通` | 同上 | 见上 |
| `收到远端媒体流，开始显示画面 ✅` | **成功** | —— |

## 端口冲突说明

- EXE 默认 8443。如果电脑上有 http-server / nginx 等开发服务占着 8443，EXE 会**自动改用 8444、8445…**，并在顶部「本机地址」显示**实际端口**。
- APK 通过 UDP 信标（`224.0.0.100:8444`，每 2s）自动拿到 EXE 实际端口，**无需手动改任何东西**。

## 已知限制

- **未签名**：EXE 与 APK 均为 debug 签名，Windows 可能弹「未知发布者」，选「仍要运行」。
- **APK 进程需存活**：游戏资源与信令代理都由 APK 本地服务提供。跳 PICO 浏览器后 APK 在后台跑，被系统回收会导致画面断。
- **右下角调试缩略图**：正式版改 `src/core/constants.js` 里 `CAST.THUMB = false` 再打包。
- **直连路径不支持 PICO 浏览器**（PICO 浏览器无 WebXR；用 APK 路径进 VR）。如头显是 PICO 且用路径②，需在桌面 Chrome / Edge 测。
