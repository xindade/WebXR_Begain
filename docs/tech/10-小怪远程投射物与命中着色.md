# 10 · 小怪远程投射物与命中着色（第三十五修）

> 需求原话：「幽灵和章鱼套用忍者的发射方式，幽灵扔紫色鬼火，章鱼扔黑色墨汁，
> 命中玩家后视野周围会短暂着色一下（紫/黑）。每次只能由最靠近玩家的怪物发射，伤害为 5。」

---

## 0. 一句话结论

幽灵怪（鬼火）与章鱼怪（墨汁）复用忍者手里剑那一整套投射物通道，
**发射节奏、出生点、命中判定、谁有资格开火**全部与忍者同构；
新增的只有两件事：投射物多出两种外观/颜色，以及命中时给玩家**视野周边染一层色**。

| 小怪 | 阶段（第三十五修前） | 现在 |
|---|---|---|
| 忍者怪 ninja | ✅ 出现→蓄力→投掷→闪现 | 不变（只改用统一通道，伤害仍为 `SHURIKEN.DAMAGE`） |
| 幽灵怪 ghost | 只有隐身，无攻击 | ✅ 隐身 → 蓄力(显形 2s) → 投**紫色鬼火** → 回隐身 |
| 章鱼怪 octopus | 只会靠近，无攻击 | ✅ 边靠近边蓄力 → 每 3s 喷**黑色墨汁**（1s 蓄力） |
| 龙头怪 dragonhead | ❌ 无技能 | ❌ **仍未实现**（造云 / 火球）—— 本修唯一剩下的空档 |

## 2. 发射规则：同种怪里只有最靠近玩家的那一只开火

`balloons.isNearestLauncher(b)`（第三十五修由 `isNearestNinja` 泛化而来）：

- 只在**同一 behavior** 的怪之间比较距离 —— 幽灵的最近者**不会**拦住章鱼的最近者，反之亦然。
- 排除龙身/龙爪（`isDragonPart`）与被外部接管的（`controlled`），只算存活的。
- 判定用**平方距离**（不 sqrt），每帧每只怪各调一次，O(n²) 但 n 很小。

其他同类怪不是「哑火」而是**照常蓄力、只是不投出**：所以场上多只幽灵时会看到一群都在闪光，
只有最近的那只真的吐火 —— 这是刻意保留的「威慑感」，也避免玩家误判谁是威胁。

| 参数 | 位置 | 现值 | 含义 |
|---|---|---|---|
| `ghostFireInterval` | enemies.js | 3.0 | 幽灵开火周期(s) |
| `ghostFireCharge` | enemies.js | 2.0 | 幽灵蓄力时长(s) = **显形时长** |
| `ghostFireDamage` | enemies.js | 5 | 鬼火单发伤害 |
| `inkInterval` | enemies.js | 3.0 | 章鱼开火周期(s) |
| `inkDuration` | enemies.js | 1.0 | 章鱼蓄力时长(s) |
| `inkDamage` | enemies.js | 5 | 墨汁单发伤害 |

⚠ **幽灵的蓄力窗口 = 可被击中的窗口**：`revealed` 直接由蓄力窗口推导，
隐身期间子弹打不中它（`game._collide` 过滤 `!revealed`）。
所以调大 `ghostFireCharge` 会同时把它变成「更好打但更常打你」的怪。

## 3. 投射物通道（`src/game/projectiles.js`）

`ProjectileManager.spawn(kind, 出生点, 目标点, opts?)` → `update(dt, 玩家位置)` → 命中回调 `(伤害, kind)`。

| kind | 发射者 | 视觉 | 伤害来源 | 视野着色 |
|---|---|---|---|---|
| `shuriken` | 忍者怪 | 4 角星 + 金属材质，绕飞行方向自旋 | `SHURIKEN.DAMAGE`(3) | 无 |
| `ghostfire` | 幽灵怪 | 紫色自发光球 + 加色光晕 | `enemies.ghostFireDamage`(5) | 紫 `0xb46bff` |
| `ink` | 章鱼怪 | 近黑低多边形墨团，翻滚 | `enemies.inkDamage`(5) | 黑 `0x05050c` |

要点：

- **几何/材质全部模块级共享**，实例只持有 `scale` / 位置 / 速度 —— 每发新建几何会带来 GC 压力（这里是热循环）。
- 出生点由调用方给（怪头顶 `y + 1.0×缩放 + 0.3`），方向由 `lookAt` + 归一化得到；速度 = 方向 × `SPEED`。
- 命中判定是**点距**（`position.distanceTo(playerPos) <= HIT_RADIUS`），不是射线，
  所以 `SPEED` 不能大到「一帧跨过玩家」：现有 12~14 m/s、60~72fps 下每帧 0.2m，远小于命中半径 0.7~0.8m。
- 伤害优先级：调用方传入的 `opts.damage`（来自 enemies.js）> `constants` 里的 `DAMAGE` 兜底。
- 音效**暂时复用**手里剑的投掷/命中音（`playShurikenThrow/Hit`）。要给鬼火/墨汁配专属音效，
  在 `audio.js` 加 `playGhostFireThrow` 等并在 `ProjectileManager.spawn/update` 按 kind 分支即可（未做）。

## 4. 命中着色（`src/vr/vignette.js`）

### 4.1 为什么不能用一个 DOM 遮罩

头显里看到的是 XR 合成画面，页面上的 DOM 层在沉浸态**不可见**
（同 `winBanner.js` / `wrist-ui.js` 的结论：DOM HUD 只对桌面预览有效）。
所以必须做**场景内**的物体。

### 4.2 做法：相机子节点上的 Sprite

- `camera.add(sprite)` —— 相机是 `rig` 的子节点（`game.js: rig.add(world.camera)`），
  而 three 在 XR 里每帧会把头显位姿写回用户相机并 `updateMatrixWorld(true)`，
  所以挂在相机下的 Sprite **永远停在视野正前方**，转头/走动都跟着走（不需要每帧手动摆位）。
- `depthTest:false` + `depthWrite:false` + `renderOrder:5000` —— 压在一切物体（含 Boss、通关横幅）之上。
- `NormalBlending`（**不是**加色）—— 加色混合下黑色等于不可见，墨汁就白做了。
- 贴图是一张「白 + alpha」的径向渐变，颜色交给 `SpriteMaterial.color` 决定 → 一张图染任意色。
  渐变：中心 0~42% 完全透明（不挡视线/不影响瞄准）→ 74% 半透明 → 93% 满 → 边缘回收一点避免硬边。

### 4.3 尺寸跟着 FOV 走

`half = DIST × tan(fov/2) × MARGIN`，`scale = (half×2×ASPECT, half×2)`。
XR 下 three 会把 `camera.fov` **改写成单眼 FOV**，所以着色期间每帧重算一次（成本可忽略）。

| 参数 | 位置 | 现值 | 含义 |
|---|---|---|---|
| `VIGNETTE.ENABLED` | constants / userConfig | true | 总开关（false = 只扣血、不着色） |
| `VIGNETTE.DIST` | 同上 | 0.42 | 距相机距离(m)：越小越像「眼睛被打花」，越大越像「面前有块玻璃」 |
| `VIGNETTE.MARGIN` | 同上 | 1.18 | 尺寸余量（>1 保证铺满视野） |
| `VIGNETTE.ASPECT` | 同上 | 1.15 | 宽高比（XR 单眼约 1.0~1.2） |
| `VIGNETTE.OPACITY` | 同上 | 0.55 | 峰值不透明度 |
| `VIGNETTE.RISE` | 同上 | 0.10 | 上色时间(s) |
| `VIGNETTE.FADE` | 同上 | 0.55 | 褪色时间(s) |

## 5. 配置链路：改哪个值，要不要重新打包

```
constants.js（默认值） ←── deepMerge ── userConfig.js（PC 端可下发）
        ▲
        └── PROJECTILE.GHOST_FIRE / INK / VIGNETTE
enemies.js（每只怪的节奏与伤害：ghostFireInterval / inkDamage …）—— 也在下发范围内
```

| 想改的东西 | 改哪里 | 要重打 APK 吗 |
|---|---|---|
| 鬼火/墨汁的速度、大小、颜色、着色强度与时长 | `userConfig.js` 的 `PROJECTILE.*` | **不用**（PC 端 `/api/config/dump` 下发，刷新页面即生效） |
| 某只怪的开火周期、蓄力时长、单发伤害 | `userConfig.js`？不再有——这里改 `enemies.js`（`src/content/`，在下发范围内） | **不用** |
| 投射物外观几何、着色层的实现方式、发射/门禁逻辑 | `src/game/projectiles.js`、`src/vr/vignette.js`、`src/game/balloons.js` | **要**（这些文件不在 `CONFIG_MANIFEST` 里） |

> `CONFIG_MANIFEST = ['src/content/', 'src/core/userConfig.js']`（见 `docs/tech/09`）。
> `constants.js` / `game.js` / `balloons.js` / 两个新文件都不在清单内。

## 6. 踩坑清单

1. **别顺手改忍者的伤害。** `enemies.js` 里曾有一个从未生效的 `shurikenDamage: 5`，
   而忍者实际吃的是 `SHURIKEN.DAMAGE`（3）。统一通道时若让 `shurikenDamage` 生效，
   忍者伤害会从 3 悄悄变成 5 —— 六关的难度会被无痕改掉。本修的处理：删掉该字段，
   `_throwProjectile` 对 `shuriken` 一律回落到 `SHURIKEN.DAMAGE`，并用测试锁住。
2. **着色层必须用 NormalBlending。** 用加色混合时黑色（墨汁）完全不显示。
3. **着色层必须挂相机、不能挂 rig。** 挂 rig 只跟位置不跟转头 → 染色的方向会跟视野错位。
4. **`depthTest:false` 是必需的**，否则贴近脸的大怪或 Boss 模型会挡住着色层。
5. **幽灵的 `revealed` 与蓄力窗口是同一个量**，别把它们拆成两套计时（改一处忘另一处 → 隐形怪被打）。
6. **投射物速度上限受「点距命中」约束**：`SPEED × dt` 必须显著小于 `HIT_RADIUS`，
   否则高速投射物会在两帧之间跨过玩家而判定不到（当前余量约 3 倍）。

## 7. 验证方法

自动测试（`npm test`，含本修新增的 `tests/projectiles.test.mjs`，共 7 项）：

- 多只幽灵/章鱼同场 → 只有最靠近玩家的那只能投出，且**两类互不干扰**。
- 忍者仍投手里剑、伤害仍等于 `SHURIKEN.DAMAGE`、且不触发着色。
- 幽灵只在蓄力窗口内 `revealed`（显形期 = 攻击窗口），蓄力结束才投出。
- 命中回调带 `(伤害, kind)`；`opts.damage` 覆盖生效；命中即回收；未命中按 `MAX_LIFE` 回收。
- 着色层挂在相机下、`depthTest:false`、渐亮到 ≈`OPACITY` 再褪回 0，且 FOV 变大会跟着放大。

现场看这几条：

1. 第 8 关（幽灵）与第 10 关（章鱼）：怪会先亮起头顶光球（紫 / 深色），约 1~2s 后吐出投射物。
2. 被打中时**视野四周**出现一层颜色（紫 / 黑），中心视野清晰；约 0.65s 褪掉。
3. 同屏 2 只以上同类怪时，只有离你最近的那只真的吐东西。
4. 幽灵隐身时打不中它，显形（蓄力）时能打中 —— 与旧版一致。
