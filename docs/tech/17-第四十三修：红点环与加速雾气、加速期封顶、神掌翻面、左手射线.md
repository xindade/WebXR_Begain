## 0. 一句话结论

- 连杀计数从「一块贴在枪管上的贴图牌子」换成**枪身红点环**：10 个小球 = 1 个 `InstancedMesh`（1 次 draw call），
  未点亮的点写**零缩放矩阵**（不是改透明度，也不是逐实例 visible）；
  集齐 → 整圈闪一下 → 枪身开始**向后飘雾**（8 片软光斑，1 个 `InstancedMesh`，只在加速的 3 秒内可见）。
- 连杀规则抽成纯函数 `advanceStreak()`：加速期间**封顶** `BOOST_CARRY_MAX`（默认 5）且**永不二次触发**。
- 如来神掌：越过玩家后**冻结朝向**（原先每帧朝相机 → 穿过瞬间翻 180°）。
- 左手射线：`SHOOT.OFFHAND_RAY = false` → 非射击手那条整条不画（主手照旧，它是真正的瞄准基准）。
- 现场调角：新增 `?aim=x,y,z`（或 `?aimx=` / `?aimy=` / `?aimz=`）URL 覆盖 → 落到 `AIM.FORCE`
  （优先级最高、不落盘）→ **只影响带着该参数的那台设备**，PICO 的启动地址不带它就是原样。

## 1. 红点环 + 加速雾气（替换「枪管大牌子」）

### 1.1 为什么不接着用贴图牌子

第四十二修把「连杀 X/10」画成一块 256×128 的贴图牌子挂在枪管上。现场两个问题：

| 问题 | 原因 |
|---|---|
| 牌子太大、挡视线 | 一块面片贴在枪上，物理尺寸跟枪一样大 |
| 每次数字变化都要重绘 canvas + 上传纹理 | `CanvasTexture.needsUpdate` 每次都传一整张 256×128 |

### 1.2 现在的做法

| 元素 | 实现 | 开销 |
|---|---|---|
| 红点（每杀一个亮一个） | 10 个小球 = **一个 `InstancedMesh`**；点亮的点写「环上位置 + 点径」矩阵，未点亮的写**零缩放矩阵** | 1 次 draw call；不显示时 `visible=false` 即 0 次 |
| 集齐闪光 | 整圈放大 `FLASH_SCALE` 倍 + 材质透明度淡出 `FLASH_TIME` | 复用同一批实例，0 额外开销 |
| 加速雾气 | 8 片软光斑（径向渐变 canvas → 加色混合）= 一个 `InstancedMesh` | 1 次 draw call，只在加速 3 秒内可见 |

**环的位置怎么定**（不需要知道 `Ak枪.glb` 的内部朝向）：

```
包围盒最长轴        = 枪管轴（枪一定是长条）
朝 -Z 的那一端      = 枪口
环心                = 包围盒中心 + 轴 × 轴长 × (ALONG - 0.5)      // ALONG 0.5 = 正中，1 = 枪口端
环平面基向量        = u（+Y 投影到垂直于轴的平面）、w = axis × u
第 i 个点的角度      = i / n × 2π（从 u 方向起）
环半径              = 枪身横截面最大半宽 × RING_FRAC(1.45)      // >1 才在枪身外面
点径                = 环半径 × DOT_FRAC(0.28)
```

### 1.3 「集齐」的判据为什么不能看连杀数

`game._bulletKill()` 在触发那一帧就把 `_bulletStreak` 清成 0，所以计数器**看不到「10」这个数**
（上一帧还是 9，这一帧已经 0）。判据改成「**新一次加速开始**」：

```js
const until = game._rapidUntil || 0;
if (until !== this._lastUntil) {          // 加速的结束时刻变了 = 新一次加速
  this._lastUntil = until;
  if (boostLeft > 0) this._flashT = 0;    // → 整圈闪一下
}
```

### 1.4 雾气为什么用「加色混合 + 逐实例调暗」淡出

雾气、火花、碎片都是同一类东西（寿命短、量大）。**淡出绝不能改材质透明度** —— 材质是共享的，
`transparent/opacity` 一变 three 就要重编译着色器（现场就是掉帧）。加色混合下「把实例颜色调暗」= 变透明，
且零重编译（与 15 号文档 §2.1 的结论一致）。

## 2. 加速期间封顶：不许「无限续杯」

### 2.1 原实现的问题

`_bulletKill()` 里连杀计数在加速期间**照常累加** → 只要在 3 秒加速里再杀 10 个，
就能立刻再触发一次加速 → 手不停 = 永远在加速里。

### 2.2 修法：把规则抽成纯函数

`src/game/rapidFire.js`：

```js
export function advanceStreak(prev, boosting, cfg = RAPID_FIRE) {
  const need = Math.max(1, cfg.KILLS | 0);
  const p = Math.max(0, prev | 0);
  if (boosting) {
    // 上限 = min(BOOST_CARRY_MAX, need-1)：need-1 保证加速期永远攒不满（不会二次触发）
    const cap = Math.min(need - 1, Number.isFinite(raw) ? Math.max(0, raw | 0) : Math.floor(need / 2));
    if (p >= cap) return { next: p, triggered: false };
    return { next: p + 1, triggered: false };
  }
  const next = p + 1;
  if (next >= need) return { next: 0, triggered: true };
  return { next, triggered: false };
}
```

| 状态 | 计数上限 | 会不会触发 |
|---|---|---|
| 平时 | `KILLS`(10) | 会（触发后清零重新攒） |
| 加速期间 | `BOOST_CARRY_MAX`(5) | **永不触发** |

> 为什么单独成文件：`game.js` 在模块级就会建 canvas / 挂场景，Node 里 import 不了。
> 规则抽出来之后「封顶 / 永不二次触发 / 加速结束后再攒够还会触发」这三条都能直接单测。

## 3. 如来神掌：越过玩家后翻面

### 3.1 现象与根因

掌图从 `START_POS(0,0,-30)` 沿 +Z 飞到 `END_POS(0,0,+30)`，中途**穿过玩家站位**。
而 `_faceCamera()` 每帧让 plane 的 +Z（法线）指向相机 —— 穿过那一刻「相机在掌图的哪一侧」反转，
指向相机的方向**掉头**，`setFromUnitVectors` 立刻给出一个 180° 的姿态 ⇒ 现场看到的「翻转一下」。

### 3.2 修法：越过之后冻结

```js
if (BUDDHA.LATCH_FACING !== false) {
  _faceNow.set(0, 0, 1).applyQuaternion(mesh.quaternion);   // 当前法线
  if (_faceNow.dot(_faceTmp) < 0) return;                   // 夹角 > 90° ⇒ 已越过去 → 冻结
}
```

- 没越过玩家：照旧每帧朝相机（玩家转头/移动时仍然对齐）；
- 越过玩家：保持越过前的朝向，不再翻面（此时玩家看到的是掌图背面，但**没有任何瞬间旋转**）；
- `BUDDHA.LATCH_FACING = false` 可回到旧行为（测试里用它做反证：关掉后 `angleTo ≈ π`）。

## 4. 左手射线隐去

原实现：两只手各挂一条 `THREE.Line`，主手红色（套瞄准补偿角）、另一手青色（不套角）。
现场定稿：**左手那条光不需要**。

`SHOOT.OFFHAND_RAY = false`：

```js
ray.visible = shooting || SHOOT.OFFHAND_RAY !== false;
```

- 主手（`shootingHand`）照旧可见 —— 它是「所见即所打」的可见证据（子弹方向与它同源）；
- 非射击手整条不画（不是改颜色、也不是缩短），要恢复把开关改回 `true` 即可；
- 创建时也按该开关给初值，避免「手柄未连接时闪一下青线」。

## 5. 现场调瞄准角（换 Quest 之后）

### 5.1 三层优先级（唯一取值出口 `deviceProfile.getAimDeg()`）

```
① AIM.FORCE（URL ?aim= / userConfig 里的 FORCE）      ← 排障/现场试角，优先级最高、不落盘
② AIM.BY_DEVICE[设备槽]（pico / quest / steamvr / unknown）
③ SHOOT.RIGHT_PITCH_DEG（只给 x，y/z = 0）
```

### 5.2 URL 现场覆盖（本修新增）

在头显浏览器地址栏里加参数即可，**不用重打包、不用重发内容包、刷新即丢**：

| 写法 | 含义 |
|---|---|
| `?aim=14,-14,0` | x,y,z 三轴一次写完（缺的轴不覆盖） |
| `?aim=20,,5` | 只覆盖 x 与 z（中间留空 = 跳过） |
| `?aimx=20&aimy=-14` | 只覆盖 x / y（`z` 保持设备槽默认值） |

例：`http://localhost:8080/?cast=1&pc=192.168.31.228&aimx=20&aimy=-14`

**为什么不会波及 PICO**：这个覆盖只作用于「带着该参数打开的页面」。
PICO 的启动地址由 APK 拼装、不带 `aim*`，所以它的固化角完全不受影响；
反过来调 PICO 时也一样 —— 两边互不干扰，不必为了试 Quest 去改 PICO 槽。

### 5.3 定稿之后

把试出来的数字写进 `src/core/userConfig.js` 的 `AIM.BY_DEVICE.quest`（要重发内容包，见 09 号文档）。
当前 Quest 槽 = `{ x: 14, y: -14, z: 0 }`（2026-09-24 在 Quest 3 上实测）。

> ⚠ 槽是**按厂牌**分的（Quest / Quest 2 / 3 / Pro 共用一个槽），而不同世代的 Touch 手柄
> targetRay↔grip 的相对姿态并不完全一致。若换机型后发现还是偏，直接用 `?aim=` 现场量一组，
> 再决定是覆盖 `quest` 槽还是钉死 `AIM.DEVICE`。

### 5.4 排障怎么看

`[AIM]` 日志现在会打出**生效角**，而不只是槽位与证据：

```
[AIM] 设备槽=quest（证据=inputSource.profiles）… → 生效角 x=14 y=-14 z=0（来源 AIM.BY_DEVICE.quest）
[AIM] 设备槽=quest（AIM.DEVICE 锁定=quest）…   → 生效角 x=20 y=-14 z=0（来源 AIM.FORCE）
```

页面上能看到日志的位置：2D 页面日志面板、PC 端镜像/直播页的日志、`?devui=1` 的调试面板。

## 7. 踩坑（照抄代码前必读）

1. **「集齐」判据不能看连杀数**：`game` 在触发那一帧就把 `_bulletStreak` 清零，计数器永远看不到 10。
   改看 `_rapidUntil` 是否变化（= 新一次加速）。
2. **`InstancedMesh` 没有「逐实例 visible」**：隐藏一个点只能写**零缩放矩阵**（或把它挪到视野外）。
   闪光按 `dt` 计时（不是 `gameTime`），否则暂停/待机态下会卡在半途。
3. **加色混合下「调暗实例色 = 淡出」**：不要为了淡出去改共享材质的 `opacity`（触发着色器重编译 → 掉帧）。
4. **`mist.instanceColor` 必须在构造时就创建**（构造里先 `setColorAt` 一遍）：
   否则首帧写入 `instanceColor` 才创建属性 → 材质多一次重编译。
5. **`barrelMount()` 的语义本修变了**：`ALONG` 现在是「0=枪托端 / 0.5=正中 / 1=枪口端」，
   旧的 `SIZE_FRAC` / `OFFSET_UP`（贴图牌子用的自动尺寸与抬高）已废弃，返回值改成
   `{position, axis, length, radius, ringRadius, dotSize}`。
6. **URL 参数解析不能写 `Number(q.get(k))`**：`q.get()` 取不到时返回 `null`，`Number(null) === 0`
   —— 会把「没写这轴」误当成 0。必须先判 `null` / 空串。
7. **Node 单测里 import `buddhaFx.js` 会炸**：该文件在**模块级**用 `TextureLoader` 预载贴图，
   three 的 `ImageLoader` 要 `document.createElementNS('...','img')` + `addEventListener`。
   `tests/register.mjs` 的 DOM 桩已补上这两个（否则「掌图朝向」这类纯逻辑没法单测）。
8. **CRLF 文件**：`src/game/buddhaFx.js`、`src/vr/rightGun.js`、`src/core/userConfig.js` 是 CRLF；
   改它们的脚本必须「读入归一成 LF → 打补丁 → 写回前转回 CRLF」。
