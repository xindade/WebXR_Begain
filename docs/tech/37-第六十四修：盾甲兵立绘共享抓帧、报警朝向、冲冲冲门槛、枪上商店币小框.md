## 2. 逐条拆解

### 2.1 盾甲兵立绘：骑士与铁甲兵卡**共用同一张**（第六十三修只做了一半）

**现场症状**：第 3 关商店里，盾甲兵卡「只显示了盾牌的」——骑士那半边是空的。

**关键线索**：同一关的**铁甲兵卡**（用的也是 `Model/骑士.glb`）是**正常**的。
两张卡抓的是**同一个 GLB**，只有盾甲兵那张是空的 ⇒ 失败的不是「骑士模型」，而是「**第二次抓同一个模型**」。

**为什么会有第二次**：第六十三修把整卡缓存改成了「每个模型各自兜底」，但缓存键仍是
`portraitKey(spec)` = `url` 或 `url|shieldModel`：

```
铁甲兵 → 键 'Model/骑士.glb'                  → 抓一次骑士
盾甲兵 → 键 'Model/骑士.glb|Model/盾牌.glb'   → 又抓一次骑士 + 一次盾牌   ← 骑士被抓了两遍
```

**修法（两条一起）**：

1. **单模型抓帧按 url 共享**：`captureModel(renderer, url, say)` 用 `_modelCache`（`url -> Promise`）去重，
   铁甲兵与盾甲兵**拿到的是同一个 Promise**。重活一关只做一次，进店更稳。
2. **空抓重试一次**：`captureOne(..., tries = 2)` 里用 `opaquePixels(canvas) > 0` 当**成功判据**
   （`captureGLB` 只在「第 0 帧几乎全透明」时 reject，但交给我们的 canvas 仍可能是空的），
   空了就隔 `PORTRAIT_STEP_MS` 再抓一把，两把都空才判失败 → 交回退。

另外合成结果也报一次像素数（`合成完成（骑士 有 · 盾牌 有，不透明像素 …）`）：
现场只要看到「只剩盾牌」，一条留痕就能区分是**骑士那张空了**还是**骑士画上去了但被裁/被挡**。

> ⚠ 反面提醒：`_modelCache` 是**按 url** 共享的，所以**同一个模型两张卡是一荣俱荣**。
> 这是有意的（骑士本来就只有一份），失败仍然不缓存（`_modelCache.delete(url)`）⇒ 下次进店还能再试。

### 2.2 ★ 内圈报警的朝向口径：报警调用里**重复取反**了一次（真 bug）

**现场症状**：「基础怪的爆炸音有时候听着在左边，实际只有前面有，有时候右边也是。」
（现场说的「爆炸音」= 小怪逼近内圈时那两声「滴滴」，见 `game/dangerAlarm.js`。）

**分区算法本身没错**：`sectorOf()` 手性有单测锁着（`tests/danger-alarm.test.mjs`），也用真角度验过。
**错在调用方** `game._updateDangerAlarm`：

```js
this.world.camera.getWorldDirection(this._fwd);
// 相机前向是 -Z（getWorldDirection 给 +Z）→ 取反才是玩家的真实面朝方向   ← ★ 这句注释是错的
{ x: pp.x, z: pp.z, fx: -this._fwd.x, fz: -this._fwd.z, inner: R }
```

three 的实现里，**`Camera` 重写了 `getWorldDirection`**（`Object3D` 的那份返回 +Z，`Camera` 那份 `.negate()`）：

```js
// vendor/three.module.js
class Object3D { getWorldDirection(t){ …; return t.set(e[8], e[9], e[10]).normalize(); } }
class Camera  extends Object3D { getWorldDirection(t) { return super.getWorldDirection(t).negate(); } }
```

⇒ 相机上拿到的**已经是真实朝向**，再 negate 一次 = 把玩家的**前/后、左/右整体转 180°**。
怪在正前，会被判成「脑后」；本该整片落在「前」扇区的怪，会从**侧向**（左/右声像）吱出来 ——
正是现场描述的「听着在左边，实际只有前面有」。

**修法**：直接用 `this._fwd`（并更正注释）。实测确认（单测里也钉住了）：
`PerspectiveCamera.lookAt(0,0,-1)` → `getWorldDirection() = (0,0,-1)`，**已经是对的**。

> ⚠ 同一文件里另外两处（选项卡生成 `_enterCard` / 中场抽卡）也写着「取反」，但它们把向量交给
> `cards.open(pp, forward, …)`，而 `open()` 里**根本没有用这个参数**（`forward` 是死参数），
> 所以那两处**没有实际影响**。本次**只动报警这一处**，不去碰无关代码。

### 2.3 「冲冲冲」门槛：跟着**本关杂鱼配额**走，不再是写死的 10 只

**现场症状**：语音只在「某一处」（Boss 成批召唤那种场面）能听到。

**真因**：门槛写死 `THRESHOLD: 10`，但这个门槛是在**三层出怪改造之前**定的。改造（第四十六修）之后，
普通关的杂鱼改走「按配额滴流」——**补满即停**，而配额 = 内圈 + 外圈
（`SPAWN_RING` / `waves.innerQuota + outerQuota`，前期约 **6~12 只**），玩家边打边补
⇒ 场上**很少**同时站够 10 只。唯一能一次涌出十几只的是 **Boss 成批召唤** ⇒ 于是「只有那一处听得见」。

**修法**：门槛改成拿本关配额当尺子（纯函数 `game/basicVoice.js`，可单测）：

```
need = clamp( round(本关杂鱼配额 × RATIO), MIN, THRESHOLD )
     = clamp( round( (innerQuota + outerQuota) × 0.6 ), 4, 10 )
```

- 配额很小（Boss 关不走滴流 / 没有 `waves`）→ 落到下限 `MIN = 4`，照样能喊；
- 配额很大（后期）→ 封顶 `THRESHOLD = 10`，怪一多也不会无限循环喊（另有 `PAUSE` 兜着）。

同时加了一行留痕：`[冲冲冲] 基础怪 N 只 ≥ 门槛 M（本关配额 Q）` —— 现场一眼就知道响没响、门槛是多少。

### 2.4 枪上的「商店币」小信息框

**现场口径**：「显示在枪支左侧信息框**往前一点、往右一点**，以枪支为它的显示框中心点，**单独一个小信息框**。」

**做法**：新模块 `src/vr/shopCoinBadge.js`，与技能信息框（`vr/skillHint.js`）**共用同一套定位算法**
（`vr/streakCounter.barrelMount`：量枪模型包围盒 → 取最长轴当枪管轴 → 沿轴取 `ALONG` → 沿「玩家左手边」偏 `LATERAL_GAP`）：

| 相对信息框 | 实现 | 现场读作 |
|---|---|---|
| 往前一点 | `ALONG 0.5 → 0.68`（更靠枪口） | 比信息框更靠前 |
| 往右一点 | `LATERAL_GAP 0.07 → 0.005`（更贴枪身） | 从玩家视角往右挪 |
| 单独一个小框 | 自己的模块 + 自己的物理尺寸（`0.24 × 0.075 m`） | 一块独立小牌子 |

- 牌子画布**复用商店区域牌子那套** `cardDraft.makeBadge`（这次给它加了可选第三参 `size = { w, h }`，
  不传时行为**完全不变**）；物理宽高比必须保持 **3.2**（= 画布 512×160）才不会被拉伸。
- 牌子挂在 **grip**（与信息框同父、同 `renderOrder`），位置是「枪空间 → grip 空间」换算出来的
  —— 手填 grip 坐标必然飘到枪上方（整把枪在 `GUN.POSITION.y = -0.25`，即手腕下方 25cm）。
- **只在商店关显示**：`game.update` 每帧下发 `rightGun.setShopCoin(this.shopMode, this.shopCoin)`；
  `makeBadge.set()` 内部去重（文字没变不重绘、不重传贴图），所以每帧调也不花钱。

## 4. 踩坑

1. **`Camera.getWorldDirection` 已经取负**（`Camera` 重写了 `Object3D` 那份）。
   写「相机前向是 -Z，所以要取反」的注释前，先确认用的是**哪种相机 API**。
2. **别只看 `captureGLB` 有没有 reject**：它只校验「第 0 帧不透明像素 > 1%」，
   但真正交给卡面的是**它拷出来的那张 canvas** —— 空图仍可能正常返回。判据要用 `opaquePixels(canvas) > 0`。
3. **同一个模型被不同卡抓到两次**：缓存键里带 `shieldModel` 就会这样。凡「同一份资源」都该按资源 url 去重。
4. **门槛写死值会随上游改造失效**：`THRESHOLD: 10` 是三层出怪**之前**定的；出怪密度一改，
   这类「绝对数量」的门槛就形同虚设。能用**相对量**（配额 × 比例）就别写死绝对值。
5. **枪上的面板/牌子一律不要手填 grip 坐标**：整把枪在 `GUN.POSITION.y = -0.25`，
   手填必然飘到枪上方（第六十一修踩过一次，本轮的商店币框继续沿用自动定位）。
6. **`makeBadge` 的物理尺寸三处要一致**：牌子宽高比必须等于画布宽高比 3.2，否则文字被拉伸。
