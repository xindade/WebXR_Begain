## 一、非商店关常显：显隐判据从「是不是商店关」换成「在不在局内」

第六十四修的口径是 `game.update` 每帧下发 `rightGun.setShopCoin(this.shopMode, this.shopCoin)` ——
`shopMode` 只在第 3 / 9 / 15 关为真，所以小框在其它 15 关根本不显示，这正是现场要改的点。

现在判据抽成 `game._shopCoinBadgeOn()`：

```js
/** 小框显隐：局内常显（现场要求非商店关也看得到商店币）；菜单 / 结束 / 开场影片期间收起 */
_shopCoinBadgeOn() {
  return this.state === 'playing' || this.state === 'card';
}
```

* `state` 的全部取值：`menu` / `intro` / `playing` / `card` / `over` —— 只有 `playing` 与 `card`（抽卡）算「局内」。
* 开场影片与穿云是 `intro` ⇒ 收起（那时还没有商店币可看，也不该占视野）。
* 显隐本身仍由 `ShopCoinBadge.show(on)` 做**差值判断**，每帧调也不会白白改 `visible`。

## 二、击杀金点：**真实值即时入账，显示值等落地**

这是本轮的核心。现场要的是「金点飞到，数字才变」，但**账目不能等动画** —— 商店扣款、切关、一局清零
都读 `game.shopCoin`，一旦为了动画延后入账，就会出现「钱买不到东西 / 数字比实际多」这类真 bug。

所以拆成两个值：

| 值 | 归属 | 语义 |
|---|---|---|
| `game.shopCoin` | 真实值 | **即时**入账（`_addShopCoin` 里 `this.shopCoin += amount`），HUD 与商店都读它 |
| `ShopCoinBadge._shown` | 显示值 | 玩家眼下看到的数，**允许落后**真实值几帧，由 `advanceShown` 推进 |

### 2.1 显示值推进（纯函数，可单测）

`src/game/shopCoinDisplay.js`（新）：

```js
export function advanceShown(shown, total, inflight, landed = 0) {
  const t = Math.max(0, Math.round(total || 0));
  let s = Math.max(0, Math.round(shown || 0)) + Math.max(0, Math.round(landed || 0));
  if (!((inflight | 0) > 0) || s > t) s = t;   // 没有在飞的金点 / 显示值超过真实值 → 对齐
  return s;
}
```

**关键设计：兜底对齐靠 `inflight === 0`，而不是靠「最后一颗金点落地时记得补账」。**
这条兜底一次性覆盖了所有「金点没了」的情形：

* 金点全落地 → 显示值一帧对齐到真实值；
* 金点池满（`ORB.POOL`）被并进别人的槽 → 落地时金额更大，不影响；
* 中途切关 / 重开 / 回菜单（`fx.clear()`）→ 在飞的金点直接消失，但金额早已入账 ⇒ 下一帧显示值就是真实值；
* `ORB.ENABLED=false`（不飞金点）→ `inflight` 恒为 0 ⇒ 数字立刻变 = 第六十四修及以前的行为；
* 商店花钱（真实值变小）→ `s > t` 时**只能降到真实值**，显示值永远不会虚高。

### 2.2 金点本体：`CoinOrbFx`（`src/game/fx.js`，新）

| 设计点 | 做法 | 为什么 |
|---|---|---|
| 终点 | **每帧**取小框的世界坐标（`targetOf` 回调） | 枪拿在手上一直在动，取一次快照的话金点会飞向一个「枪曾经在那儿」的虚空点 |
| 落地 | `t/dur` 时间归一 + smoothstep：位置 = 起点 → **当帧**终点 的插值 | 目标在动也**保证在 `DUR` 秒内精确落到终点上**；不需要「距离阈值」那种会漏判（阈值 > 单帧位移就永远收不了尾）的收尾 |
| 弧线 | `position.y += ARC × sin(π k)` | 有弧线才像「飞过去」，否则像「贴脸消失」 |
| 池化 | `ORB.POOL` 个 Sprite 槽；池满 → 金额并进**最老**的槽（`born` 序号最小） | 帧内不 new、不增长；钱一分不丢，只是共用一颗光点飞过去（`tests/coin-orb.test.mjs` 锁了「3×10 + 并进的 7 = 37 全额落地」） |
| 可见性 | `depthTest:false` + `renderOrder 998` | 隔着怪 / 枪模型也看得见 —— 「我的钱飞过来了」必须看得见 |
| 空转 | 没有在飞的金点时**连终点都不问** | 省掉每帧一次 `getWorldPosition` 的矩阵上行；绝大多数帧都属于这种 |

> 为什么这里可以用 Sprite（`fx.js` 开头的纪律是「粒子别用 Sprite」）：
> Sprite 无法实例化，但金点要 ① 永远面向玩家（billboard）② 各自独立淡出 ③ 同屏只有个位数
> —— 与 `HealPlusFx`（飞行加号）同一类问题、同一套解法（池化 Sprite），不是「每帧几百粒」的粒子。

### 2.3 接线（顺序不能反）

`_updateFx()` 是**帧末**调用（注释里写明「必须是帧末，位置才是本帧最终值」），正好满足「先知道本帧落地多少钱、再推数字」：

```js
_updateFx(dt) {
  if (!this.fx) { this._updateShopCoinBadge(0); return; }
  const coinLanded = this.fx.update(dt, this._coinTarget);   // ① 先推进金点，拿到本帧落地金额
  this._updateShopCoinBadge(coinLanded);                     // ② 再推数字 + 下发显隐
  ...
}
```

`this._coinTarget = (out) => (this.rightGun ? this.rightGun.coinBadgeWorldPos(out) : null)` ——
拿不到（小框没建 / 没挂上）就返回 `null`，`CoinOrbFx` 会**立刻落地**：数字照变，只是没有飞行过程，绝不卡账。

三条入账路径都补上了「击杀位置」（不传位置 = 不飞金点，数字立刻变）：

| 路径 | 调用 |
|---|---|
| 普通击杀 | `this._addShopCoin(_killScore, balloon.mesh.position)` |
| 龙 Boss 部件 | `this._addShopCoin(balloon.score, balloon.mesh.position)` |
| 聚宝盆 | `this._addShopCoin(bonus, balloon.mesh.position)` |

## 三、「冲冲冲」口径更正（★ 已被第六十六修覆盖）

第六十四 / 六十五修这两轮都把现场那句话读成了「门槛调高低」的问题，方向是**反的**。
第六十六修现场把口径说清楚了（原话）：

> 「冲冲冲的语音，只有第三关的脸谱Boss的第一阶段才会有，其它关卡中不要放，因为太吵了。」

也就是说这不是「让它更容易响」，而是**位置门禁**：除脸谱 Boss 第一阶段外，其它关卡 / 阶段要**完全静音**。
（本节原先那条「普通关必然喊得出来」的用例已**删除** —— 它与现场口径矛盾。）

本节的 `need = clamp(round(配额 × RATIO), MIN, THRESHOLD)` 门槛**保留**（它管「凑够多少只才喊」），
但**只在门禁放行后**才参与判断；门禁 `game._basicVoiceAllowed()` 排在数怪之前。
完整口径见 [`39-第六十六修：商店币小框改右侧镜像半尺寸、冲冲冲限定脸谱Boss第一阶段.md`](./39-第六十六修：商店币小框改右侧镜像半尺寸、冲冲冲限定脸谱Boss第一阶段.md)。

## 四、顺手修掉：引导金点的起飞点在玩家背后

`game._goldToCards()`（精英批次清空 → 金点飞向选项卡）里本来这样写：

```js
this.world.camera.getWorldDirection(dir);
dir.negate();   // 旧注释：相机前向是 -Z（getWorldDirection 给 +Z，同 _enterCard 的处理）
from.addScaledVector(dir, 1.2);
```

注释是**错的**：three 的 `Camera` 重写了 `getWorldDirection`（内部 `.negate()`），相机上拿到的**已经是「看向的方向」**
（实测：`lookAt(0,0,-1)` 得 `(0,0,-1)`；`Object3D` 那份才给 +Z —— 同 `tests/alarm-facing.test.mjs` 的结论）。
所以那次再 `negate()` 等于把金点放到**玩家背后 1.2m** 起飞，与注释想要的「准星前方」正好相反。本轮去掉那次取反。

> 同一文件里另有 `cards.open(playerPos, forward, ...)` 的位置参数也传了取反值，但 `cardDraft.open()` 的
> `forward` 形参**通篇没有被读过**（死参数），无实际影响，本次不动。

## 验证方法

1. **桌面/头显进第 1 关**：枪身左侧的「商店币 N」小框**直接就在**（第六十四修时它在非商店关是不显示的）。
2. **打怪**：击杀瞬间数字**不动**，一颗金色小点从怪的位置划一道弧线飞到枪上，**贴到牌子那一帧**数字跳上去。
3. **连续杀多只**：金点会一枚一枚飞，数字一格一格往上追（不是一次性跳到位）。
4. **商店关（第 3/9/15 关）花钱**：买完数字立刻降到新余额（花钱不飞金点、也不许虚高）。
5. **第 3 关盾甲兵卡**：仍是「骑士 + 盾牌」合成立绘（第六十四修），留痕有 `合成完成（骑士 有 · 盾牌 有 …）`。
6. **留痕搜 `[冲冲冲]`**：**普通关应当一行都没有**（第六十六修加了门禁 —— 只有脸谱 Boss 蓝阶段才允许响）。
