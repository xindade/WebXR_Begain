## 0. 一句话结论

四条改动都是同一句话：**在不加剧单帧负担的前提下加观感**。

- 曳光不再「固定长度向后拖」，而是**最多拖到出生点**（不足 `MIN_BACK` 干脆不画），枪口焰再沿枪口方向**前移** `FORWARD`；
- 神掌命中改为**入队分帧结算**（每帧最多 `BUDDHA.MAX_DAMAGE_PER_FRAME` 只）+ 伤害数字**贴图上传节流**（每帧最多 `UPLOAD_PER_FRAME` 张）；
- 中场预警必须是**场景内 Sprite**（沉浸态里页面 DOM 不可见，同 `winBanner` / 腕表面板 / 命中着色 的结论）；
- 连杀加速改写的是**真实节流源** `input._gunCooldown`（不是改 HUD 显示），枪管计数面板**只在数值变化时重绘**。

## 1. 问题 1：曳光 / 枪口焰穿到枪管后方

### 1.1 现象

按住扳机持续射击时，金色尾迹**从弹头一直拖到枪管后侧**，短促扫射时更明显，像「光从枪管屁股漏出来」。

### 1.2 根因（两个独立成因叠在一起）

| 成因 | 说明 |
|---|---|
| **出生点在枪管内部** | `SHOOT.SPAWN_OFFSET = 0.5` —— 子弹出生点故意放在枪管里（否则子弹会从枪口外凭空出现）。 |
| **曳光是「定长后拖」** | 档2 的曳光按固定 `FX.TRACER.LENGTH = 0.55 m` 从弹头沿 `-dir` 拖出（这样长度与帧率无关，见 15 号文档 §4.2）。 |

两条叠加：弹头刚出膛的那几帧仍在枪管内部/刚过枪口，而固定 0.55m 的尾迹已经**整条落在枪管里**，
再被 `depthTest` 一比，就从枪管后侧漏出来。枪口焰同理 —— 光斑中心在枪管内部，大半个被枪管自身挡住。

### 1.3 修法

1. `src/game/bullets.js`：子弹对象新增 `origin`，`spawn()` 时 `b.origin.copy(position)`（出生点）。
2. `src/game/game.js::_updateFx()`：画子弹曳光时传 `back = b.pos.distanceTo(b.origin)`。
3. `src/game/fx.js::TracerTail.add(pos, dir, colorHex, back)`：

   ```js
   const maxBack = back == null ? this.cfg.LENGTH : back;
   const len = Math.min(maxBack, this.cfg.LENGTH);
   if (!(len > (this.cfg.MIN_BACK || 0))) return false;   // 太短 → 不画
   ```

   弹头离出生点不足 `LENGTH` 时，尾迹**最多拖到出生点**（≈枪口），永远不越过枪管。
4. 敌方投射物**不传 `back`** → 走 `back == null` 分支，行为与旧版**逐字节一致**（拖满 `LENGTH`）。
5. `MuzzleFlash.flash(pos, dir)`：给了方向就沿单位方向前移 `FX.MUZZLE.FORWARD = 0.20 m`；
   不给方向时**保持原行为**（落在传入坐标）—— 老调用点不受影响。

> `MIN_BACK = 0.10` 的意义：出膛那几帧尾迹长度只有几厘米，画出来是一坨贴片而不是光条，
> 观感反而更差。索性不画 —— 那几帧的「出膛感」交给枪口焰。

## 2. 问题 2：如来神掌释放杀敌时一瞬间卡顿

### 2.1 根因

一掌罩住几十只怪时，原来在**同一帧**里对每只怪各跑一遍：

```
takeDamage() → damageNumbers.spawn()（256×128 canvas 重绘 + CanvasTexture 上传 ≈128 KB/张）
             → 击杀碎片爆发 → 击杀音效
```

单帧几十次纹理上传 = 一次 GPU 尖峰。在 PICO 4（XR2）上就表现成「神掌一放就卡一下」——
而它恰恰是**一掌秒一群**的技能，命中数天然是全场最大的一次。

### 2.2 修法甲：伤害数字贴图上传节流

`src/game/damageNumbers.js` 新增 `_uploads`（本帧已上传数）/ `peakUploads`（自检峰值）/ 条目级 `_texDirty`：

- 每帧预算 `DAMAGE_NUMBER.UPLOAD_PER_FRAME = 6` 张；
- `_draw(e)` 末尾 `_flushUploads(e)`（排除自己），预算内则 `tex.needsUpdate = true; _texDirty = false`，
  超预算则标 `_texDirty = true` **延后**；
- `update(dt)` 开头 `_uploads = 0` 再补上一帧欠的账；
- `game._updateFx()` 帧末调 `flushUploads()` 兜底。

> ⚠ **未上传的条目必须隐形**：`_texDirty` 的条目强制 `material.opacity = 0`。
> 伤害数字是**对象池复用**的（canvas 与贴图都是同一批），贴图没上传就意味着
> 屏幕上会显示**上一轮那只怪的旧数字**。这是本修最容易踩的坑，测试里专门锁了一条。

> ⚠ `spawn()` 里给 `opacity` 赋值必须放在 `_draw(e)` **之后** —— 上传发生在 `_draw` 内部，
> 顺序写反会把「本帧刚上传成功」的条目又抹成透明。

### 2.3 修法乙：神掌命中分帧结算

`src/game/game.js` 新增 `_buddhaQueue`：

- `_updateBuddhaFx()` 命中判定通过时**只入队** `{ b, dmg }`（不再当场 `takeDamage`）；
- `_drainBuddhaQueue()` 每帧只消费 `BUDDHA.MAX_DAMAGE_PER_FRAME = 6` 个：
  复查 `b.alive && this.balloons.list.includes(b)`（排队期间可能已被连锁击杀 / Boss 收尾带走）→
  `takeDamage` → `_damageFeedback`（数字+命中音）→ 击杀则 `_onKilled`；
- `_updateBuddhaFx()` 函数末尾**同步调用一次** `_drainBuddhaQueue()`，`_update()` 里再调一次兜底
  （保证「同帧定乾坤」的语义不退化，任何直接调 `_updateBuddhaFx` 的地方——含测试——行为不变）。

效果：几十只怪摊到 **5~8 帧（≈0.1s）**内逐个弹出数字、逐个结算击杀。肉眼几乎无感，
但单帧上传数从「几十」压到「≤6 + ≤6」。

## 3. 新功能 1：关卡过半的「更强的敌人来袭」横幅

### 3.1 为什么必须做成场景内 Sprite

头显**沉浸态**下页面 DOM 不可见（`winBanner` / 腕表面板 / 命中着色 都踩过这条）。
所以「必须让玩家看到」的提示只能在场景里做 —— 本次用 Sprite。

### 3.2 判据（纯函数，便于单测）

`src/game/warningBanner.js` 导出 `midWarningDue(elapsed, seconds, alreadyWarned)`：

```js
if (alreadyWarned) return false;
if (!(Number(seconds) > 0)) return false;              // 机制关 / Boss 关没有倒计时
return Number(elapsed) >= Number(seconds) * MID_WARNING.AT;
```

接线在 `game._updatePlaying()`（紧跟 `waves.update()`）：

```js
if (MID_WARNING.ENABLED && !this.normalTest) {
  const lv = LEVELS[this.levelIndex];
  if (lv && !isBoss(lv) && !isLaser(lv)
      && midWarningDue(this.waves.elapsed, levelSecondsOf(lv.n), this._midWarned)) {
    this._midWarned = true;
    this.midWarning?.show();
  }
}
```

- **机制关 3/9/15**（`isLaser`）与 **Boss 关 6/12/18**（`isBoss`）**不弹** —— 它们没有「过半」这个概念
  （`LEVEL_SECONDS.BY_LEVEL` 里根本没有它们的时长，自然取不到窗口）。
- **每关只弹一次**：`_midWarned` 把关，`_loadLevel()` 复位；`_restartLevel()` / `toMenu()` / `start()`
  一律 `midWarning.hide()` 收掉残留。

### 3.3 实现要点

| 项 | 做法 | 为什么 |
|---|---|---|
| 载体 | `THREE.Sprite` + 一张 1024×256 canvas | 永远面向玩家；不用猜朝向 |
| 复用 | **同一个** Sprite + 同一张 canvas / 贴图，文本变了才重绘 | 18 关 × 每关一次，若每次新建 canvas+texture 等于白送 18 次上传 |
| 位置 | 每帧 `camera 世界位置 + 世界方向 × DIST(2.6m)` | 出现在**准星正前方**，不跟随枪 |
| 时间轴 | 淡入 `FADE_IN(0.25s)` → 满亮 → 淡出 `FADE_OUT(0.35s)`，总时长 `SECONDS(2s)` | 够看清、不挡视野 |
| 层级 | `renderOrder = 900` | 压在场景之上、通关横幅（1000）之下 |

## 4. 新功能 2：连杀加速（子弹击杀 10 人 → 射速 +50%）

### 4.1 只认子弹击杀

接线在 `game._collide()`（子弹命中气球处），**紧随** `_onKilled`：

```js
if (killed) this._onKilled(hitBalloon);
if (killed) this._bulletKill(hitBalloon);   // 第四十二修：连杀加速只认子弹击杀
```

- 技能 / 如来神掌 / 激光剑 / 爆炸 杀的一律**不计数，也不打断**连杀（避免「技能抢人头=断连」的挫败感）；
- `_bulletKill()`：`_bulletStreak++` 并记时刻；满 `KILLS(10)` → 计数**清零重新攒**（可连触发）
  → `_rapidUntil = _gameTime + SECONDS` → `_setRapidMul(1 / MULT)` → `audio.playRapidFire()` → 写日志；
- `_tickRapidFire()`（每帧）：`GAP(6s)` 内没有新的子弹击杀 → 计数清零；
  加速到期 → `_setRapidMul(1)` 还原（幂等，用 `_rapidMul` 记住当前生效值，避免每帧刷 `input`）。

### 4.2 加速改的是「真实节流源」

`input.setFireRateMul(mul)` 改写的是 `input._gunCooldown = _baseGunCooldown × mul`
（`mul < 1` = 冷却更短 = 更快）。**不是**改 HUD 上那个数字 —— 玩家 DPS 表
（`攻击力 × 多重弹道 × 射速`）会跟着真实变化。测试里专门锁了「改写的是 `_gunCooldown`、还原后回到基线」。

### 4.3 枪管上的计数面板

> ⚠ **第四十三修已把它换掉了**：现场反馈「牌子太大」，改成**枪身红点环 + 加速雾气**，
> 并且加速期间连杀封顶 —— 见 [17 · 第四十三修](./17-第四十三修：红点环与加速雾气、加速期封顶、神掌翻面、左手射线.md)。
> 本节保留作为历史记录（贴图牌子的做法与 `barrelMount` 自动标定的思路在那一修继续沿用）。

`src/vr/streakCounter.js`：

- Sprite 挂在 `RightGun.root`（跟着枪走），显示「连杀 X/10」；触发后切换成金色的「射速 +50% · 3.0s」倒计时；
- **自动标定枪管挂点**（不需要知道 `Ak枪.glb` 内部朝向/尺寸）：

  ```
  模型在 root 空间的包围盒 → 最长轴 = 枪管轴
                          → 取朝 -Z（手柄前方）的那一端 = 枪口
                          → 落点 = 中心 + 轴向 × 轴长 × 0.5 × ALONG(0.55)
  ```

- ⚠ **不能用 `Box3.setFromObject`** —— 那给的是**世界坐标**（枪挂手上会随玩家动），
  我们要的是「相对枪自己」的包围盒，所以逐 mesh 用相对矩阵（`model.matrixWorld⁻¹ × mesh.matrixWorld`）换算；
- **只在显示的数变了才重绘 canvas**（连杀 +1 / 倒计时每 0.1s 一次），常态下**零纹理上传** ——
  这点和每帧重绘的 `skillHint` 不同；
- 模型加载失败时 `place(null)` 退回固定枪管位 `(0, 0.06, -0.30)`，不崩也不悬空。

### 4.4 奖励音

`src/vr/audio.js::playRapidFire()`（现场觉得不好听直接改这一段即可）：

| 段 | 内容 | 作用 |
|---|---|---|
| ① 上行三连叮 | `triangle` 1174.7 / 1568 / 2093 Hz，间隔 0.06s | 「达成」的正反馈主音 |
| ② 金属过载 | `sawtooth` 220→1320 Hz，低通 600→7000 Hz 扫开 | 「枪械上膛/过热」的速度感 |
| ③ 收尾气流 | 噪声 + `highpass 1200` | 收干净，不拖泥带水 |

> 全程**不用方波** —— 击杀音 `thump` 是那一路音色，方波会和它撞在一起听不出区别。

## 5. 参数表

全部在 `src/core/constants.js` 的 `_OVERRIDES` 白名单里 → 现场改 `src/core/userConfig.js` 同名键即可热调

| `RAPID_FIRE.MULT / SECONDS` | 1.5 / 3 | 射速倍率（1.5 = 2 发/秒 → 3 发/秒）/ 持续秒数 |

| `RAPID_FIRE.COUNTER.OFFSET_UP` | 0.05 | 相对枪管轴抬高（比例，正 = 朝手柄 +Y 即玩家上方） |

## 6. 踩坑（照抄代码前必读）

1. **`add(pos, dir, color, back)` 不传 `back` 时必须是旧语义**（拖满 `LENGTH`）——
   敌方投射物在用三参调用，改错会把手里剑/鬼火/墨汁的尾迹一起改短。
2. **伤害数字「贴图没上传」的条目必须隐形**（`opacity = 0`）。漏了这一条，视觉上会出现
   「打死怪的一瞬间先闪一下上一只怪的数字」——而且只在高压帧出现，极难复现定位。
3. **`spawn()` 里 `opacity` 必须写在 `_draw()` 之后**（上传发生在 `_draw` 内）。
4. **神掌队列消费时必须复查 `alive` + `balloons.list.includes(b)`** —— 排队期间目标可能已被
   连锁击杀/Boss 收尾移除，直接用会二次结算甚至计分两次。
5. **枪管挂点必须用相对矩阵，不能用 `Box3.setFromObject`**（世界坐标 ≠ root 空间坐标）。
6. **计数面板别每帧重绘**：`update()` 里先比 `_streak` 与 0.1s 粒度的倒计时，值没变直接 return。
7. **横幅 Sprite 的 `renderOrder`**：900（场景之上、通关横幅 1000 之下）；别忘 `depthTest:false`。
8. **CRLF 文件**：`src/game/bullets.js`、`src/vr/rightGun.js`、`src/core/userConfig.js` 是 CRLF；
   改它们的脚本必须「读入归一成 LF → 打补丁 → 写回前转回 CRLF」，否则 `git diff` 变成整文件重写。

## 7. 验证方法

### 7.1 自动化（`npm test` → 104/104）

`tests/stage3.test.mjs`（17 例）：

- **曳光**：后拖长度受 `back` 限制、最多拖到出生点；不足 `MIN_BACK` 不画（返回 false）；
  **不传 `back` 时与旧版一致**（拖满 `LENGTH`，保护敌方投射物）；
- **枪口焰**：给了方向沿 `FORWARD` 前移（且是单位方向前移，不受向量长度影响）；不给方向保持原行为；
- **上传节流**：同帧上传数封顶在 `UPLOAD_PER_FRAME`、超出的延后一帧；
  未上传条目**隐形**；预算内（常规命中）**当帧就上传、零延迟**；
- **中场预警**：判据四态（过半前 false / 过半 true / 已弹过 false / 无倒计时 false）；
  横幅 `show` 后淡入、到点自动 `hide`；
- **连杀**：配置合理（10 连杀 / ×1.5 / 3s / 有断连超时）；
  改写的是真实节流源 `_gunCooldown`、还原后回到基线；奖励音真的产出音频节点且无非法包络；
- **枪管挂点**：取最长轴当枪管轴、落点在「中心→枪口」的 `ALONG` 比例处；
  从真实模型（Group + 长条 Mesh）能量出包围盒；
- **计数面板**：有连杀/加速才显示，值没变**不重绘**（零纹理上传）；模型加载不出来时退回固定枪管位。

### 7.2 现场（头显内）

| 判据 | 期望 |
