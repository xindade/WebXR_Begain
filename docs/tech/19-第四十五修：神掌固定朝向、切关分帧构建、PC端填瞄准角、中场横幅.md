## 0. 一句话结论

1. **神掌朝向**：前两修都在调「**什么时候**冻结朝向」，方向错了 —— 问题在「**冻结下来的那个姿态本身就是斜的**」。
   本修不再算时机，而是**直接把姿态算出来**：局部 `+Z` = 飞行轴、局部 `+Y` = `f × right`（垂直于飞行轴且尽量朝上），
   从头到尾**一个姿态**、永不变换 ⇒ 与地面恒成直角；越过玩家后看到的是掌的背面，正是「把它正过来」要的效果。
2. **卡顿**：影片交接与切关的卡顿是**同一件事** —— 「本关场景构建 + 首帧着色器编译」全挤在**一帧同步做完**，
   而那一帧画面还没被雾盖住。两步修：① 雾**提前到快照之前**建（不进差集 ⇒ 不参与淡入 ⇒ 第一帧就满不透明）；
   ② 本关物体拆成**任务表，穿云窗内每帧建一组**，全程被雾盖着。
3. **瞄准角**：PC 端 EXE 界面新增 PICO / Quest 六格输入 + 保存。存档走「**本机覆盖表 + 下发给头显前套用**」，
   **不动服务器清单也能立刻生效**，且重启 EXE 依然有效。
4. **横幅**：真因是判据写反 —— `if (MID_WARNING.ENABLED && !this.normalTest)` 里的 `normalTest` 是「**普通关**」的
   代名词（`NORMAL_TEST.enabled` 默认开），于是**所有普通关都被排除**，横幅从未弹过。改成只看 `MID_WARNING.ENABLED`。

## 1. 如来神掌：改成「固定姿态」，不再调闩锁时机

### 1.1 为什么前两修都白改

| 修 | 思路 | 现场结果 |
|---|---|---|
| 第四十三修 | 判据「当前法线 · 指向相机 `< 0`」→ 冻结 | **从不触发**：相机不在掌图飞行线上（掌沿 `y=0`、相机 `y≈1.6`），该点积恒 > 0.8 ⇒ 一直每帧朝相机 ⇒ 仰面转到 ~180°（「翻一下」） |
| 第四十四修 | 判据改成「掌图中心 − 相机」在**飞行轴**上的投影符号 → 越过即一次性闩锁 | 判据**生效了**，但冻下来的是「越过那一刻的**朝相机**姿态」，而那个姿态**本身就是斜的** |

关键：**「每帧朝相机」这个解法先天带一个绕飞行轴的回转角。**
`setFromUnitVectors(+Z, 指向相机)` 走的是**最短弧**，把「相机方向里的那点 `+Y` 分量」解成了**绕飞行轴的倾角**。
相机在 `y≈1.6`、掌图在 `y=0` ⇒ 这个倾角必然存在。
所以无论在哪一刻冻结，冻下来的都是**一个斜着的掌** —— 现场看到的「与地面成锐角」就是它。

**结论：改判据、加闩锁都治不了这个病，只有把回转量钉死。**

### 1.2 现在的实现（`src/game/buddhaFx.js`）

```js
// ① f = 飞行轴（START_POS→END_POS，默认 +Z，见 _computeTravelDir）
// ② right = worldUp × f        （水平右向）
// ③ up    = f × right          （⟂ f ⇒ 掌面必然含竖直分量）
// ④ basis = (right, up, f)     → mesh.quaternion.setFromRotationMatrix(basis)
_rightV.crossVectors(_worldUp, _fwdV);
if (_rightV.lengthSq() < 1e-8) _rightV.crossVectors(_refUp, _fwdV);  // 垂直飞行：换参考轴 (_refUp = (0,0,1))
upV.crossVectors(_fwdV, _rightV).normalize();
_basis.makeBasis(_rightV, _upV, _fwdV);      // 局部 +Z = 掌面法线 = 飞行轴
mesh.quaternion.setFromRotationMatrix(_basis);
```

- 局部 `+Z`（掌图 `PlaneGeometry` 的法线）**恒等于飞行轴** ⇒ 掌是「一面朝向玩家的墙」，正对飞行方向；
- 局部 `+Y` = 掌面内的「上」 ⇒ 水平飞行时恰好等于世界 `+Y`（证：`f × (worldUp × f) = worldUp − f(f·worldUp)`，水平飞行时 `f·worldUp = 0`）；
- 因此掌面**始终包含竖直方向**，与地面恒成直角，既不翻滚、也不中途变斜。

**「越过玩家后会上下颠倒」怎么处理？** 不处理 —— 那是**看背面**，是固定姿态的必然结果，也是用户要的
（原话：「让它正过来不就行了」＝ 让它别再翻，而不是让它转回来）。

兜底：给不出 `travelDir`（起终点重合）或 `BUDDHA.LATCH_FACING === false` 时，退回旧的「每帧朝相机」实现（仅作对照/回退）。

## 2. 影片播完 / 切关卡顿：雾先盖住，物体分帧建

### 2.1 现象与根因

`_loadLevel()` 原来把本关的全部构建**同步**做完：`OpeningModel` / `LaserLevel`（含第九关的 `GlassGrid`）/
`DragonBoss` / `waves.startLevel()`，再叠上**这些新物体的首帧着色器编译**和 `_snapshotState()` 的遍历。
这一整坨挤在**同一帧**；而那一帧**雾还没盖上来**（改造前 `CloudFx` 自己也是**从 0 淡入**的，等于没有遮），
于是玩家直接看到一次冻结 —— 影片播完的那一下、每次切关的那一下，都是它。

### 2.2 三处改动（缺一不可）

**① 雾在建快照之前就起（顺序不能反）**

```js
const cover = !!CLOUD.ENABLED;
if (cover) { this._introActive = true; this._introT = 0; /* dispose 旧的 */ this.cloudFx = new CloudFx(...); this.cloudFx.start(...); }
const _sceneBefore = new Set(this.world.scene.children);   // ← 雾已经在里面了
```

雾**不进**「本关新物体」的差集 ⇒ **不参与 `extendFadeRoots` 的淡入** ⇒ 第一帧就是满不透明，
把后面几帧的构建**实打实盖住**。顺序反过来（先快照、后建雾）就是白改：雾会自己从 0 淡入，等于没遮。

**② 本关构建拆成任务表，每帧跑一组**

```js
const tasks = [];
// ① L3/9/15 的 OpeningModel（语音 URL 仍在同步段排定）→ ② 非 Boss 非激光关的 _spawnPortals
// → ③ 互斥三选一（激光几何 / 龙 Boss / waves.startLevel）→ ④ 非激光关 _snapshotState()
if (cover) this._levelTasks = tasks;      // 分帧跑（见 _pumpLevelTasks）
else for (const t of tasks) t();          // 无穿云：同步连跑，与改造前完全一致（效果不丢）
```

`_pumpLevelTasks()` 在 `_updatePlaying` 的穿云分支里、`cloudFx.update(dt)` **之前**每帧调一次（`shift()` 一个任务）；
`_introT >= CLOUD.INTRO_DELAY` 时 `_drainLevelTasks()` 兜底把剩下的**一次性补完**（正常 4 秒足够，防半成品关卡）。
两组任务都各自 `try/catch`：**某一组失败只记录、不中断**，避免半成品关卡把渲染循环带崩。

**③ 淡入登记改成「先开一张空表并强开」**

```js
this.world.setFadeRoots([], true);    // 第二参 forceOn（本修改动就是为它）
```

`world.setFadeRoots(roots, forceOn = false)` 里 `this._fadeOn = forceOn || this._fadeMats.length > 0;`。
不这样做的话：调用这一刻**差集还是空的** ⇒ `_fadeOn = false` ⇒ `extendFadeRoots()` 直接早退
⇒ 后面几帧才建出来的物体**不会被登记淡入**，于是「啪」地满显 —— 白遮。

### 2.3 与前几修的关系

`_startIntroVideo` / `_commitIntroToLevel` / `HANDOFF_DELAY_S` / `DISPOSE_DELAY_S` /
`warmSkyPano()`（第四十四修）**一行未改**，本修是**叠加**在它们之上：预热负责「影片期间把已知重活做掉」，
分帧负责「影片结束/切关那一帧别一次做完剩下的」。

## 3. PC 端 EXE 界面直接填瞄准角

### 3.1 为什么存「覆盖表」而不是直接改文件

正式包走的是**服务器清单**：`userConfig.js` 落在 `userData/manifest/`，而且**每次启动 + 每局结束都会重拉一份**。
直接改那份文件，下一次拉取就冲掉了。所以改成三层：

| 层 | 位置 | 作用 |
|---|---|---|
| ① 覆盖表 | `userData/cast-pc-config.json` 的 `cfg.aim` | 重启 EXE 依然有效 |
| ② 下发前套用 | `/api/config/dump` 的 `push()` + 清单静态路的 `userConfig.js` 响应 | 头显真正拿到的是**套用后**的文本 |
| ③ 保存时 best-effort 写盘 | 清单缓存（`userData/manifest/`）+ 游戏目录（`CONFIG_ROOT`） | 让那份「可提交 / 可上传服务器」的文件也同步 |

⚠ **②必须重算 `sha256` 与 `size`**（都按**套用后**的内容算），否则头显自校验失败、整包被拒。

### 3.2 界面与 IPC

- `renderer/index.html` 新增 `#aimbox`（PICO x/y/z + Quest x/y/z）+ 保存按钮 + 状态行，并加入 `body.pure #aimbox { display:none }`（纯净模式不显示）；
- `renderer/renderer.js`：`AIM_INPUTS` / `renderAim()` / `refreshAim()` / `aimSave.onclick` ——
  **留空 = 该轴不动**（所以可以一次只调一个轴）；
- `preload.js` 暴露 `aimGet` / `aimSet`；`main.js` 新增 IPC `aim:get` / `aim:set`；
- `aim:set` 里落盘 + **`rotateSession('EXE 界面改了瞄准补偿角')`** —— 换局号 ⇒ 头显下次问配置时**整包重下**（不换它会一直吃缓存）。

### 3.3 与 `tools/set-aim.js` 的关系

两边**共用同一个纯正则模块** `tools/cast-pc/lib/aim-config.cjs`
（`SLOTS` / `AIM_REL` / `findSlot` / `readAxes` / `rewriteAxes` / `readSlots` / `sanitize` / `applyPatch`）：
不 eval、原位替换、保留缩进与行尾注释、幂等。`tools/set-aim.js` 改为 `import` 它（原来的本地副本已删）。

## 4. 中场横幅复活（`MID_WARNING`）

```js
if (MID_WARNING.ENABLED) {
  const lv = LEVELS[this.levelIndex];
  if (lv && !isBoss(lv) && !isLaser(lv)
      && midWarningDue(this.waves.elapsed, levelSecondsOf(lv.n), this._midWarned)) { /* show() */ }
}
```

- 改动只有一处：**去掉 `&& !this.normalTest`**。
- `this.normalTest = (this.waves.mode === 'normalTest')`，而 `NORMAL_TEST.enabled` **默认 true**
  ⇒ 普通关全部 `normalTest === true` ⇒ 原来那句等于「普通关从不弹」。**它是「普通关」的代名词，不是调试残留。**
- 机制关（`isLaser`）/ Boss 关（`isBoss`）**没有倒计时**，由 `midWarningDue(elapsed, seconds <= 0)` 自然挡住；
  另外还有 `!isBoss && !isLaser` 的显式前置判据，双保险。

## 6. 踩坑（本修踩到的）

| 坑 | 说明 |
|---|---|
| **冻结一个「本来就错的」姿态没有意义** | 第四十三/四十四修都在调「什么时候冻」。真正的病是「每帧朝相机」**先天带一个绕飞行轴的回转角**（最短弧把相机方向的 `+Y` 解成倾角）⇒ 冻下来的永远是斜的。**要钉死回转量，不是钉死时机** |
| **`setFromUnitVectors` 的 roll 不确定** | 它只保证一个轴对齐、**不约束绕该轴的回转**。凡是「让某个轴朝相机/朝目标」的写法，都会留下这个自由度 |
| **雾必须建在快照之前** | 否则它自己进差集、自己从 0 淡入 = **等于没遮**（这就是改造前卡顿看得见的原因） |
| **差集为空会把 `_fadeOn` 置 false** | `setFadeRoots([])` 之后 `extendFadeRoots()` 早退 ⇒ 分帧建出的物体**啪地满显** ⇒ 本修给它加了 `forceOn` 第二参 |
| **分帧任务必须 try/catch** | 一组失败若把 `_loadLevel` 的调用方炸掉，会留下半成品关卡带崩渲染循环；现在只记录 + 进日志 |
| **正式包的 `userConfig.js` 会被清单重拉覆盖** | 所以不能「直接改文件」了事；必须「覆盖表 + 下发前套用」，并且**套用后重算 `sha256`/`size`**，否则头显自校验失败 |
| **`asar: true` ⇒ 改渲染层必须重出 EXE** | 动 `renderer/renderer.js`、`renderer/index.html`、`preload.js` 之后，`npm run dist` 不能省 |

  但若某关还有别的首帧重活（例如某个模型首次上场），仍可能残留一次卡顿 —— 现场若仍看到，按 `docs/tech/13` 的
  `warmModelGpu()` 思路继续把该模型塞进 `_buildIntroPreloadQueue`。

  `tools/set-aim.js` 改文件 + `node tools/cast-server/sync-content.js --ver <版本>` 后上传（见 `docs/tech/09`）。

- 本修**没有**新增网络协议、没有动平台上报（CMD 5/7/16）、没有动推流与主控门禁链路。
- 历史遗留（与本修无关，仍在）：`SPAWN_RING.pool = ['basic']`（小怪单一，最可能是「节奏单调」的根因）、
  第 18 关有**两份**同名 `_updateBossIntensity`（后者覆盖前者，且都读 `waves.boss` 而魔术师血量在
