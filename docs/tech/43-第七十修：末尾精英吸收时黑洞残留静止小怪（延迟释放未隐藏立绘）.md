# 第七十修 · 末尾精英吸收小怪时，黑洞残留“静止小怪”

> 现场：末尾精英出现时如果左右手放了黑洞，部分小怪会直接静止；
> 打不到、也没有伤害数字；把精英打死仍能正常过关。

---

## 1. 真因：延迟释放只摘了 3D 主体，忘了 2D 立绘

第六十八修为了削平「末尾精英出现时转头黑一下」的尖峰，把融合吸收/切关清场改成：

```js
balloons.remove(b, /* deferDispose */ true);   // 先从 list + scene 摘掉
// 下一关云雾窗里：flushRetired(2) → b.dispose()
```

这段只保证了两件事：

- `b.alive = false`，从 `balloons.list` 移除（所以不再参与命中、伤害、过关计数）；
- `scene.remove(b.mesh)`，3D 主体/血条/名牌（都是 `b.mesh` 的子节点）随之消失。

但本项目有一批敌人用的是 **DepthSprite 2D 立绘**（`DEPTH_SPRITE_TYPES` 白名单）。
立绘**不在** `b.mesh` 下面，而是和它平级挂在同一个 scene：

```js
balloon.mesh.parent.add(ds.mesh);   // 见 balloonModels.js
balloon.depthSprite = ds;
```

立绘只会在 `b.dispose()` 里被移除（`_dsScene.remove(this.depthSprite.mesh)`）。
延迟释放把 dispose 推到了**下一关**，于是：

- 小怪已经“死了”（不在 list，打不到、没伤害数字、也不挡过关）；
- 但它的 2D 立绘还留在场景里，停在最后一帧的位置；
- 黑洞会把小怪拉到洞缘并冻住 → 残影正好停在玩家视野正前方，看起来就是“静止的小怪”。

忍者蓄力球（`_chargeOrb`）也是单独挂在 `manager.scene` 上的，同一类问题。

## 2. 修法

`BalloonManager.remove(b, true)` 在把资源推进 `_retired` 之前，**立刻隐藏所有不在 `b.mesh` 下的视觉件**：

```js
if (b.mesh) b.mesh.visible = false;
if (b.depthSprite && b.depthSprite.mesh) b.depthSprite.mesh.visible = false;
if (b._chargeOrb) b._chargeOrb.visible = false;
```

这只是隐藏，不提前 dispose —— 第六十八修的分帧释放收益完全保留。

## 3. 影响面

所有走延迟释放的路径一起修好：

- 末尾精英 `_fuseSpawn()` 吸收场上小怪；
- 切关 `balloons.clear()`（此前旧关的立绘会残留到新关云雾窗，逐帧 flush 才消失）；
- 其它 `remove(b, true)` 调用。

## 4. 验证

- `tests/fade-warm.test.mjs` 第 1 项新增断言：
  - 延迟释放后 `depthSprite.mesh.visible === false`；
  - `_chargeOrb.visible === false`；
  - 仍然要等 `flushRetired()` 才真正 `dispose()`。
- 全量：**462 / 462 通过**。

## 5. 上机自测

1. 任意普通关，等到 31s 末尾横幅后、精英融合光点出现；
2. 在光点落地前后释放黑洞，让小怪被吸到洞缘；
3. 精英出现、小怪被吸收：场上不应再有静止不动的残留小怪；
4. 黑洞结束后继续正常射击/清怪，通关判定不受影响。
