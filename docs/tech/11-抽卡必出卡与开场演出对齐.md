## 0. 一句话结论

- **第九关必定出一张回血卡**：把「必出卡」从**单个 id** 扩成**id 数组**，数组里取第一张「池中仍可用」的
  （自我修复 → 生命上限）；两张都满级时退化为**战场补给**兜底卡，保证「一定有回血选项」这条规格在任何调参下都成立。
- **机制关开场语音播完 → 魔术师同步消失**：给语音元素挂 `ended`，回调里 `dispose()` 开场模型；
  语音加载失败 / 不触发 `ended` 时，仍由 `OpeningModel` 自己的 `SHOW_SECONDS`（10s）兜底。

## 2. 第九关回血保证

### 2.1 原有的「必出卡」机制，以及它的坑

`_buildCardPlan()` 早就支持 `plan.guarantee`（01 关 = `multiShot`，02 关 = `fireRate`），
`cardDraft.open()` 把它存进 `this._guarantee`，`_buildCards()` 里先固定该卡再补 2 张。

**坑在过滤**：卡池先经过 `availableAttributes(player, ids)`，**已达上限的卡会被剔除**
（`selfRepair` 上限 `regen = 10`，`hp` 上限 `maxHp = 400`）。原判据是

```js
if (g && pool.some(a => a.id === g)) { /* 必出 */ } else { /* 静默退回随机 3 张 */ }
```

→ 只要该卡满级，`guarantee` 就**一声不响地失效**。对 01/02 关无所谓（那时不可能满级），
但「第 9 关必定回血」是一条**规格**，不能靠「那时不可能满级」来兜。

### 2.2 做法：`pickCards(pool, guarantee, count)`

把选卡逻辑抽成 `src/game/cardDraft.js` 里的**纯函数**（可单测、无 THREE 依赖）：

```js
export function pickCards(pool, guarantee, count = CARD.COUNT) {
  const ids = Array.isArray(guarantee) ? guarantee : (guarantee ? [guarantee] : []);
  let gCard = ids.length ? (pool.find(a => ids.includes(a.id)) || null) : null;
  if (!gCard && ids.length > 1) gCard = RESUPPLY_CARD;   // 组保证兜底：回血卡全部满级
  const rest = pool.filter(a => a.id !== (gCard ? gCard.id : ''));
  /* 洗牌 */
  if (gCard) return [gCard, ...rest.slice(0, Math.max(0, count - 1))];
  return rest.slice(0, Math.min(count, rest.length));
}
```

- **单卡（字符串）**：语义与原来完全一致 —— 池中有则必出，没有则退回随机（01/02 关不受影响）。
- **数组**：取数组中**第一张池中可用的**，等价于「带优先级的必出组」。
- 第 9 关的接线在 `_buildCardPlan()`：

```js
} else if (lv.kind === 'boss' || lv.kind === 'laser') {
  plan = { pool: ['skillCost', 'skillDamage', 'selfRepair', 'hp'] };
  // 第9关：必定出一张回血卡（自我修复优先，其次生命上限；两张都满级时退化为战场补给）
  if (lv.n === 9) plan.guarantee = ['selfRepair', 'hp'];
}
```

### 2.3 兜底卡：`RESUPPLY_CARD`

`availableAttributes()` 里本来就有「全池满级 → 给一张回满生命的补给卡」的分支，
但它当时是**内联对象**。第三十六修把它提为导出常量：

```js
// src/content/cards.js
export const RESUPPLY_CARD = {
  id: 'resupply', label: '战场补给', desc: '回满生命，并获得3秒护盾', color: '#16a085', icon: 'hp',
  apply: p => { p.hp = p.maxHp; p.shieldTime = Math.max(p.shieldTime || 0, 3); },
};
```

一处定义、两处消费（`availableAttributes` 的满级兜底 + `pickCards` 的组保证兜底），不会漂移。

> **现实里会撞上兜底吗？** 进第 9 关前一共只有 8 次抽卡（其中第 3 关是固定技能卡，不抽属性），
> 而把 `hp` 和 `selfRepair` 都点满要 6 + 5 = 11 张 → 正常对局撞不上。
> 兜底是**规格保险**（防止以后调关卡数 / 调上限时静默破规格），不是为了日常路径。

## 3. 开场语音与魔术师动画对齐

### 3.1 根因：动画比语音长 2~4 秒

三段机制关语音的实际时长（按 WAV 头 `dataLen / byteRate` 实测）：

| 关卡 | 语音文件 | 时长 |
|---|---|---|
| 第 3 关 · 激光搭阵 | `music/魔法师激光阵语音.wav` | **7.48 s** |
| 第 9 关 · 玻璃走格子 | `music/魔法师玻璃格子.wav` | **6.17 s** |
| 第 15 关 · 九宫格翻转 | `music/魔法师九宫格.wav` | **5.90 s** |

而 `OPENING_MAGICIAN.SHOW_SECONDS = 10` → 语音讲完后魔术师**还会多站 2.5~4 秒**，这就是「不匹配」。

**两者的起点本来就是对齐的**，这一点很关键：

- 动画：`openingModel.update()` 在 `_introActive`（穿云）期间被冻结（`game.update()` 里 `&& !this._introActive`）；
- 语音：延迟到穿云结束才播（`_pendingOpenVoice` → `_startLevelAudio()`）。

所以缺的不是「同步开始」，而是**一个结束信号**。

### 3.2 做法：拿语音的 `ended` 当收场信号

`AudioManager.playVoice()` 本来就 `return el`，只是没人接。现在接住它：

```js
// _startLevelAudio()
if (this._pendingOpenVoice) {
  const _voiceEl = this.audio?.playVoice(this._pendingOpenVoice);
  this._bindOpeningVoice(_voiceEl);   // 机制关(3/9/15)：语音播完 → 魔术师同步收场
}

// 语音播完（ended）即让魔术师动画一起消失
_bindOpeningVoice(el) {
  if (!el || !this.openingModel || !OPENING_MAGICIAN.FOLLOW_VOICE) return;
  const seq = ++this._openingVoiceSeq;
  el.addEventListener('ended', () => {
    if (seq !== this._openingVoiceSeq) return;   // 已切关/已换关：回调作废
    if (this.openingModel) { this.openingModel.dispose(); this.openingModel = null; }
  }, { once: true });
}
```

### 3.3 两条安全网（缺一个都会出事）

| 风险 | 安全网 |
|---|---|
| 语音 404 / 解码失败 / 被浏览器拦了自动播放 → **`ended` 永远不触发**，魔术师永驻 | `OpeningModel` 自身的 `_t >= _showSeconds` 仍在跑 → **10s 自动消失**（`SHOW_SECONDS` 同时是兜底上限） |
| 上一关的语音还没播完就切关（3 → 9 → 15 连打）→ 旧 `ended` 回调把**新一关**的魔术师收掉 | `_openingVoiceSeq++`：**自增序号**让旧回调判定失败；配合 `{ once: true }` 顺带自动摘监听 |

清理点统一收口到一个方法，切关 / 回菜单共用：

```js
// 释放开场魔术师动画，并作废其语音联动回调（切关 / 回菜单共用）
_disposeOpening() {
  this._openingVoiceSeq++;
  if (this.openingModel) { this.openingModel.dispose(); this.openingModel = null; }
}
```

调用位置：`_loadLevel()` 头部（新模型创建**之前**）与「回菜单」清理段。

> 注意 `openingModel.dispose()` 是**幂等**的（内部 `_disposed` 守卫），
> 所以「10s 自动消失后又收到 `ended`」也不会重复释放。

## 4. 参数表

| 参数 | 位置 | 默认 | 说明 | 能否热调 |
|---|---|---|---|---|
| `OPENING_MAGICIAN.FOLLOW_VOICE` | `constants.js` / `userConfig.js` | `true` | `true`：语音播完魔术师同步消失；`false`：退回旧行为（只按 `SHOW_SECONDS` 计时） | ✅ `userConfig`（服务器清单可下发） |
| `OPENING_MAGICIAN.SHOW_SECONDS` | 同上 | `10` | 循环播放时长，同时是**语音联动的兜底上限** | ✅ |
| 第 9 关必出卡组 `['selfRepair', 'hp']` | `game.js` `_buildCardPlan()` | — | 数组顺序即优先级 | ❌ 改代码需重打 APK |
| `CARD.COUNT` | `constants.js` | `3` | 3 选 1 | ✅ |

**打包边界**：`pickCards` / `guarantee` 数组 / 语音联动都属于 `src/game/**` 代码，**不在** `CONFIG_MANIFEST`
（`['src/content/', 'src/core/userConfig.js']`）里 → **要生效必须重打 APK**；EXE 不受影响。

## 5. 踩坑清单

1. **`guarantee` 会静默失效**：凡是「必出」需求，都要先确认目标卡**没被 `availableAttributes` 过滤掉**，
   并且给一个「一张都不可用」时的退化路径。静默失效是这条链路上最贵的 bug —— 现场表现为「偶发不出」。
2. **别用 `visible = false` 藏模型**：动画还在跑、资源还在占，等于没消失。收场一律走 `dispose()`。
3. **切关必须作废旧回调**：`ended` 是异步的，`{ once: true }` 只保证「只触发一次」，不保证「触发时还是同一关」。
   用自增序号（或保存元素引用比对）判定，否则会把新一关的演出收掉。
4. **`_disposeOpening()` 的位置**：必须在新模型 `new OpeningModel(...)` **之前**，否则刚建的模型会被立刻释放。
5. **口径要区分「单卡」和「组保证」**：单卡池中没有 → 退回随机（原语义）；数组池中都没有 → 退化到兜底卡。
   两者行为不同，是有意的。
6. **兜底卡要单点定义**：`RESUPPLY_CARD` 提为导出常量，避免 `cards.js` 内联对象与 `pickCards` 各写一份而漂移。
