# 06 · 游戏内视频播放技术

> 源码：`src/game/waitingRoom.js` ｜ 参数：`constants.js` 的 `WAITING_ROOM`（+ `CAST` 的影片相关项）
> 相关：`docs/headset-video-playback.md`、`src/net/cast.js` 的 `notifyIntro()`
> 复现难度：★★★★（DOM 不可见 / 自动播放策略 / 媒体硬件争用，三个坑必须逐个实测）

---

## 1. 场景

游戏开始前有一段**开场影片**（第 1 关前的「等待房间」）：
黑底空间 + 左侧一块悬浮视频屏，玩家可在等待期间自由走动，影片结束（或失败/超时）后进入第 1 关。

看似简单，但 VR 里播放影片有三个独立难点：

| 难点 | 原因 |
|---|---|
| **DOM 在沉浸态不可见** | immersive WebXR 下浏览器页面完全被头显接管，`<video>` 标签看不见 |
| **自动播放被拦截** | 页面加载时没有用户手势，带声音的 `play()` 会被浏览器拒绝 |
| **媒体硬件争用** | 头显**解码**影片与头显**编码**直播画面，抢同一个 VPU → 影片一闪一闪 |

---

## 2. 核心方案：把视频"贴"到 3D 平面上

不能播放「DOM 里的视频」，只能播放「**3D 场景里的一块贴图**」：

```
动态 <video>（不入 DOM 也能解码）
      │
      ├── VideoTexture（主视角唯一消费者）
      │
      └── 或 CanvasTexture（镜像 2D canvas）
                    ↓
        MeshBasicMaterial.map
                    ↓
      PlaneGeometry → 场景中的「视频屏」
```

### 2.1 视频元素与屏幕

```js
_buildVideoWall() {
  const v = document.createElement('video');
  v.playsInline = true;
  v.preload = 'auto';
  v.src = WAITING_ROOM.VIDEO_URL;            // assets/intro/intro.mp4
  this._video = v;
  ...
  // 初建按 16:9 估尺寸；loadedmetadata 后按真实宽高比重新适配（防拉伸变形）
  this._applyVideoSize(16, 9);
  const mat = new THREE.MeshBasicMaterial({ map: this._texture });
  this._videoMesh = new THREE.Mesh(new THREE.PlaneGeometry(this._vw, this._vh), mat);
  // 朝向：PlaneGeometry 默认面朝 +Z，绕 Y 转 +90° 后面朝 +X（正对房间内的玩家）
  this._videoMesh.rotation.y = Math.PI / 2;
  // 位置：左墙(-X)内侧、垂直居中于 VIDEO_CENTER_Y、沿墙(Z 向)居中
  this._videoMesh.position.set(-(MOVE.BOUND_X - 0.10), WAITING_ROOM.VIDEO_CENTER_Y, 0);
  this.group.add(this._videoMesh);
}
```

> **为什么内收 10cm**：视频面离玩家钳制边界（`x = -BOUND_X`）内收 `0.10`，
> 防止玩家贴到边界时相机近裁剪面（`0.05`）把屏幕切出穿模。

### 2.2 宽高比自适应（contain）

```js
_applyVideoSize(vw, vh) {
  const ar = (vw && vh) ? vw / vh : 16 / 9;
  let w = WAITING_ROOM.VIDEO_MAX_W;
  let h = w / ar;
  if (h > WAITING_ROOM.VIDEO_MAX_H) { h = WAITING_ROOM.VIDEO_MAX_H; w = h * ar; }  // 高度受限则改按高度算
  this._vw = w; this._vh = h;                                                        // 结果写回，供 geometry 用
}

v.addEventListener('loadedmetadata', () => {
  if (this._disposed) return;
  const vw = v.videoWidth || 16, vh = v.videoHeight || 9;
  this._applyVideoSize(vw, vh);
  this._videoMesh.geometry.dispose();
  this._videoMesh.geometry = new THREE.PlaneGeometry(this._vw, this._vh);   // 重建几何
  // 同步镜像 canvas 宽高比，避免镜像画面被拉伸
  if (this._mirror) {
    this._mirror.height = Math.max(2, Math.round(this._mirrorW / (vw / vh)));
    this._paintMirrorBackground();          // 改尺寸会清空内容 → 重铺黑底
    if (this._castTex) this._castTex.needsUpdate = true;
  }
});
```

> 先按 16:9 建一个「占位尺寸」立刻可见（不至于黑屏等元数据），
> 拿到 `videoWidth/videoHeight` 后再按真实比例重建——**不改就一定会拉伸变形**。

### 2.3 色彩空间

```js
this._texture = new THREE.VideoTexture(v);
this._texture.colorSpace = THREE.SRGBColorSpace;   // 视频是 sRGB，否则画面发灰
```

## 3. ⭐ 单一消费者原则（血泪教训）

直播方案在离屏（第二个 WebGL 上下文）里也要显示这块视频屏，于是出现过**两个消费者**同时从同一个 `<video>` 取帧：

```
① 两个 GL 上下文各传一次 VideoTexture → 离屏侧交替拿到已释放缓冲 → PC 端闪
② drawImage（离屏镜像）+ VideoTexture（主视角）互相抢当前帧
   → 头显里也闪，且离屏常被抢空 → PC 端直接黑屏
```

**最终结论（2026-09-09，不要再绕回去）**：

```js
/**
 * 取帧模式：'mirror' | 'raw'
 * ⚠ 'hide' 与 'raw' 都返回 'raw'（主视角用 VideoTexture）：
 *   'hide' 只是让**直播画面**把视频屏换成纯黑，主视角取帧方式与 raw 相同。
 *   这样 <video> 只剩主视角一个消费者 —— 头显内影片正常，且 PC 端不会因跨上下文争用而闪。
 */
_pickVideoMode() {
  const m = new URLSearchParams(location.search).get('vmode') || CAST.VIDEO_MODE;
  return m === 'mirror' ? 'mirror' : 'raw';
}
```

```js
// 'hide' 时把视频屏换成纯黑（离屏渲染前后成对调用，渲染后必须传 false 还原）
_castVideoSwap(mode) {
  const mesh = this._videoMesh; if (!mesh) return;
  if (mode === 'hide') {
    if (!this._savedMat) this._savedMat = mesh.material;
    if (!this._hideMat) this._hideMat = new THREE.MeshBasicMaterial({ color: 0x000000 });
    mesh.material = this._hideMat;
    return;
  }
  if (this._savedMat) { mesh.material = this._savedMat; this._savedMat = null; }
}
```

**代价**：影片那几秒 PC 大屏看不到画面 → 用 §5 的「PC 端本地同步播放」补上。

### 镜像模式（备选，可被 URL 打开）

```js
_startMirror() {
  const draw = () => {
    if (this._disposed || !v) return;
    if (v.readyState < 2) return;          // 尚无可用帧 → 保留上一帧，不闪黑
    try {
      this._mirrorCtx.drawImage(v, 0, 0, this._mirror.width, this._mirror.height);
      this._castTex.needsUpdate = true;    // 关键：通知两个 GL 上下文重新上传
      this._mirrorFrames++;
    } catch (e) { this._mirrorErr = String(e?.message || e); }
  };
  if (typeof v.requestVideoFrameCallback === 'function') {
    const loop = () => { if (this._disposed) return; draw(); this._rvfcHandle = v.requestVideoFrameCallback(loop); };
    this._rvfcHandle = v.requestVideoFrameCallback(loop);
  } else {
    this._mirrorTimer = setInterval(draw, 33);   // 兜底：约 30fps
  }
}
```

`requestVideoFrameCallback` 在**新帧呈现时**回调，天然按视频实际帧率节流（不做无用功）。

**自愈**：mirror 若在 PICO 上取不到帧（回调不触发）→ 主视角会一直是黑 canvas → **黑屏比闪烁更糟**，
所以 2.5 秒无帧自动退回 `VideoTexture`：

```js
if (this._mirrorFrames === 0 && v && v.readyState >= 2) {
  this._noFrameT = (this._noFrameT || 0) + dt;
  if (this._noFrameT > 2.5) { this._fallbackToRaw(); return; }
}
```

## 4. ⭐ 解码 × 编码争用 → 影片期间不推流

```js
// 标记「影片阶段」：cast.js 读它来决定是否暂停推流（见 CAST.PAUSE_ON_INTRO）。
// 为什么需要：影片播放时头显同时在做「视频硬件解码」与「H.264 硬件编码（推流）」，
// 两者争用同一个媒体硬件块（VPU）→ 解码输出被抢 → 头显里影片一闪一闪。
// 实测：游玩阶段（无解码）不闪；去掉 ?cast=1（无编码）也不闪 → 只有「解码 × 编码」同时存在才闪。
if (scene.userData) scene.userData.castIntro = true;
```

**已被证伪的「调参方案」**（都试过、都无效，因为动的是 GPU 侧而不是 VPU 争用）：

- 降分辨率 ❌（分辨率是 GPU 侧填充率）
- 降 fps ❌
- 关 `preserveDrawingBuffer` ❌

**正确做法**：影片期间**不做编码**，PC 大屏改播本地影片（见 §5）。

## 5. PC 端本地同步播放（影片期的替代画面）

```js
start(onDone) {
  ...
  // 通知 PC 端：开场影片开始 → 它同步播放**本地**同一段影片。
  try { window.__cast?.notifyIntro?.('play'); } catch (e) { /* 未启用直播则忽略 */ }
  ...
}

dispose() {
  ...
  // 影片结束 → 通知 PC 端停止本地影片（随后头显恢复推流，PC 端切回游戏画面）。
  // ⚠ 必须在删除 castIntro 之前发：cast.js 一看到 castIntro 消失就会开始建离屏渲染器。
  try { window.__cast?.notifyIntro?.('end'); } catch (e) { /* 未启用直播则忽略 */ }
  ...
  delete this.scene.userData.castIntro;      // 影片结束 → cast.js 恢复推流
}
```

时序：

```
头显                                             PC
 │  waitingRoom.start()
 │  ├─ notifyIntro('play') ─────────────────────► 播放本地 /assets/intro/intro.mp4
 │  ├─ 影片播放中（不编码）
 │  ├─ ended / dispose()
 │  ├─ notifyIntro('end') ──────────────────────► 400ms 后收起影片层
 │  └─ replaceTrack(游戏画面) ──────────────────► 切回游戏画面
```

- **同源前提**：PC 端播的是 `/assets/intro/intro.mp4`，要求 `serveRoot = GAME_ROOT`
  → **必须先在 EXE 里配置游戏目录**。
- **晚开补发**：头显 `onReady` 时若 `castIntro` 仍为真，会补发一次 `play`（PC 晚启动也不错过）。
- **三重兜底防影片层永久遮挡**：`end` 信令 / 本地 `ended` +1.2s / `duration + 5s` 硬收起。
- 声音默认静音，`M` 键切换。

## 6. 自动播放解锁

```js
v.play().catch(() => {
  // 有声播放被自动播放策略拦截（页面缺手势）→ 静音重试 + 首次交互取消静音
  v.muted = true;
  v.play().catch(() => finish());            // 连静音都失败 → 直接进第 1 关
  this._unmuteHandler = () => { v.muted = false; this._removeUnmuteHandler(); };
  window.addEventListener('pointerdown', this._unmuteHandler);
  window.addEventListener('keydown', this._unmuteHandler);
});
```

三层降级：**带声播放 → 静音播放 → 放弃并直接进第 1 关**（绝不软锁）。
一旦用户有任何交互（点击/按键），立刻取消静音。

## 7. 三重兜底：绝不软锁

```js
const finish = () => {
  if (this._done || this._disposed) return;    // 一次性守卫
  this._done = true;
  this._clearWatchdog();
  this._removeUnmuteHandler();
  this._onDone?.();                            // → game 进第 1 关
};

v.addEventListener('ended', finish);                                   // ① 正常结束
v.addEventListener('error', finish);                                   // ② 文件缺失/解码失败
this._watchdog = setTimeout(finish, WAITING_ROOM.WATCHDOG_MS);         // ③ 看门狗（120s）
```

`WATCHDOG_MS = 120000`（2 分钟）。无论发生什么异常，最多 2 分钟也一定进游戏。

## 8. 资源释放（VR 一体机必须做）

```js
dispose() {
  if (this._disposed) return;
  this._disposed = true;
  this._clearWatchdog();
  this._removeUnmuteHandler();
  this.scene.remove(this.group);
  this.group.traverse((o) => { if (o.isMesh) { o.geometry?.dispose(); o.material?.dispose?.(); } });
  this._texture?.dispose();
  try { window.__cast?.notifyIntro?.('end'); } catch (e) {}
  this._stopMirror();
  if (this.scene?.userData) {
    delete this.scene.userData.castVideoSwap;
    delete this.scene.userData.castIntro;      // 影片结束 → cast.js 恢复推流
  }
  this._castTex?.dispose();
  this._hideMat?.dispose();
  // 释放视频解码器：pause + 清 src + load() 触发回收
  if (this._video) {
    try { this._video.pause(); this._video.removeAttribute('src'); this._video.load(); } catch (e) {}
    this._video = null;
  }
}
```

> **`pause() + removeAttribute('src') + load()` 三连是释放解码器的标准做法**。
> 只 `pause()` 不够——一块 1080p 解码器在移动 GPU 上是很贵的资源，不释放会让后续关卡的可解码路数变少甚至失败。

## 10. 踩坑清单

| 现象 | 真因 | 结论 |
|---|---|---|
| 头显里影片全黑、只有声音 | 用 DOM `<video>` 或 canvas 没进 3D 场景 | 必须**纹理化**到 `PlaneGeometry` |
| 影片画面被拉伸变形 | 只按 16:9 建尺寸 | `loadedmetadata` 后按真实宽高比重建几何 |
| PC 端画面一闪一闪 | 两个 GL 上下文各传一次 `VideoTexture` | 单一消费者：直播侧换成纯黑 |
| 头显里也闪 + PC 端黑屏 | `drawImage`(镜像) 与 `VideoTexture`(主视角) 互抢帧 | 默认 `VIDEO_MODE='hide'`，**主视角独占** `<video>` |
| 加了直播后影片才闪 | **解码 × 编码争 VPU** | 影片期间不编码；降分辨率/降帧率/关 PDB 均**无效**（已证伪） |
| 影片那几十秒 PC 大屏没内容 | 上面那条的必然代价 | PC 端**本地播同一段影片**，靠 `intro` 信令对齐 |
| PC 端播不出影片 | 影片路径不同源（未配 `GAME_ROOT`） | 先在 EXE 里配置游戏目录 |
| 影片层永久遮挡 PC 大屏 | `end` 信令丢失 | 三重兜底：end / 本地 ended+1.2s / duration+5s |
| 无声 / 一进页面就不播 | 自动播放策略拦截 | catch → 静音重试 → 首次交互取消静音 |
| 影片卡住游戏永远不进第 1 关 | 无兜底 | 三重兜底 + 看门狗 120s |
| 后续关卡视频解码失败/卡顿 | 解码器未释放 | `pause() + removeAttribute('src') + load()` |
| 退出后 `cast.js` 报错 | 钩子没摘，仍调用已销毁对象 | `dispose` 里 `delete scene.userData.castVideoSwap` |
| 用 mirror 模式头显全黑 | PICO 上 `requestVideoFrameCallback` 不触发 | 2.5s 无帧自动退回 `raw` |

## 11. 验证方法

**基础播放（不开直播）**
- [ ] 断掉 `?cast=1`，进入等待房间：左侧出现视频屏，画面正常、无变形、有声音（或点击后有声）
- [ ] 影片结束后**必定**进入第 1 关（看到关卡开始日志）
- [ ] 把 `VIDEO_URL` 改成不存在的路径：`error` 触发，仍进入第 1 关（不卡死）
- [ ] 等待期间可自由走动，射击不产生子弹

**直播联动（开 `?cast=1`）**
- [ ] 影片期间头显内**不闪**（这是核心判据）
- [ ] 影片期间 PC 大屏播放同一段影片；影片结束后 PC 端自动切回游戏画面
- [ ] PC 端晚启动：头显进入影片时 PC 仍能收到 `play` 并开始播
- [ ] 手动杀掉 PC 端进程：头显不受影响，仍正常进入第 1 关

**释放**
- [ ] 进入第 1 关后，日志中不再出现 `[waitingRoom]` 诊断行（说明已 dispose）
- [ ] 连续进出等待房间多轮，内存/解码器无持续增长

**对照实验（排障用）**
- [ ] `?vmode=mirror`：观察镜像模式行为与自愈日志
- [ ] `?mw=320` 降镜像宽度：验证是否为带宽/取帧问题
