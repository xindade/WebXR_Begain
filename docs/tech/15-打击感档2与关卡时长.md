## 1. 关卡时长与精英波前移

### 1.1 改之前的问题

倒计时是**一个全局值**，写死在两处（各一份，语义相同）：

- `constants.SPAWN_RING.stopAt = 60`（普通关走 `_updateDpsSpawn` 时的生效值）
- `constants.NORMAL_TEST.stopAt = 60`（`SPAWN_RING.enabled=false` 时的回退分支）

消费点只有两处：`waves.js::_updateDpsSpawn`（补怪窗口 + 「时间到且场上清空即通关」）
与 `game.js`（HUD 倒计时）。所以「按关卡给时长」只需一张表 + 一个取值函数。

### 1.2 现在的口径

| 关 | 类型 | 时长 |
|---|---|---|
| 1, 2, 4, 5 | 普通 / 危机 | **40s**（原 60s，−20s） |
| 7, 8, 10, 11 | 普通 / 危机 | **50s**（原 60s，−10s） |
| 13, 14, 16, 17 | 普通 / 危机 | 60s（本轮不动） |
| 3, 9, 15 | 激光机制关 | **没有倒计时**（不在此表） |
| 6, 12, 18 | Boss 关 | **没有倒计时**（不在此表） |

- 表位置：`src/core/constants.js` 的 `LEVEL_SECONDS.BY_LEVEL`；取值 `levelSecondsOf(n)`。
- 未列出的关 → `REF_SECONDS`（60）；写 0 或删掉某关也回落到 60。
- 精英波：`ELITE_WINDOW`（5/20/40s，来自 `src/content/eliteMonsters.js`）**按比例前移**：

```
k = levelSecondsOf(n) / LEVEL_SECONDS.REF_SECONDS      // 见 levelTimeScale()
early/mid/late = ELITE_WINDOW.{early,mid,late} × k
```

| 关 | k | 前期 | 中期 | 后期 |
|---|---|---|---|---|
| 1~6 | 0.667 | 3.3s | 13.3s | **26.7s** |
| 7~10 | 0.833 | 4.2s | 16.7s | **33.3s** |
| 13 起 | 1.0 | 5s | 20s | 40s（与原样完全一致） |

> **为什么必须一起前移**：通关判据是「时间到 + 场上清空」。1~6 关改成 40s 后，原本 40s 才登场的
> 后期精英波正好顶在结束点上 —— 玩家永远见不到它。测试里专门留了一条反证用例锁住这个口径。

## 2. 档2 四项视觉打击感

| 项 | 观感 | 实现要点 |
|---|---|---|
| **曳光** | 子弹拖一条金色细光条；鬼火紫、墨汁暗紫、手里剑白 | 单位立方体长轴(Y) 用 `setFromUnitVectors` 旋到飞行方向、`scale.y = LENGTH`；**固定从弹头向后拖**，不用「上一帧→这一帧」的线段 |
| **命中火花** | 命中点溅出 3~5 粒暖金光点，0.14s 消散 | 低面数球颗粒（不用 Sprite），加色混合 + 逐实例调暗 = 淡出 |
| **击杀碎片** | 按**敌种 tint** 炸出 6~10 块方块，受重力翻滚 0.55s | 颜色取 `balloon.type.tint`（没有就兜底灰）；精英/Boss/龙 ×1.6 片 |
| **枪口焰** | 开火瞬间在**真实枪口**闪一下（0.05s） | 位置直接取 `input.shots[i].position`（与红射线/子弹同源），不是「枪模型上挂个位置」 |

### 2.1 为什么要「池化 + 实例化」

现场跑的是 PICO 4（Adreno XR2，72fps，单帧预算 ≈13.9ms）。这四项都是「每帧量大、寿命极短」：

- 一辈子只 new 一次的数组/矩阵，比每帧 `new Vector3()` 稳得多（GC 抖动会直接吃掉帧预算）；
- 一项一个 `InstancedMesh` → 1 次 draw call 装下全部实例（火花 64 粒也还是 1 次）；
- **淡出绝不能改材质透明度**：材质共享，`transparent/opacity` 变化会触发 three 着色器重编译。
  统一改成「加色混合下逐实例调暗 `instanceColor`」——加色下变暗 = 变透明，且零重编译。

### 2.2 接线点（都在既有集中入口上，没有到处撒钩子）

| 事件 | 接线点 | 说明 |
|---|---|---|
| 命中 | `game.js::_damageFeedback()` | 第 40 修已把「伤害数字 + 命中音 + 震动」集中在此 → 火花挂在同一处 |
| 击杀 | `game.js::_killFeedback()` | 已在 `_onKilled()` 首行，**所有击杀路径**（子弹/激光剑/如来神掌/自爆/脸谱子实体/龙部件）自动共享 |
| 开火 | `game.js::_updatePlaying()` | 消费 `input.shots` 的那一行之后，用同一发炮弹的枪口坐标 |
| 曳光 | `game.js::_updateFx()`（帧末） | 每帧扫一遍 `bullets.active` + `projectiles.list`，写进同一条实例网格 |
| 清理 | `start() / toMenu() / _restartLevel()` | 与 `damageNumbers.clear()` 同点调用 `fx.clear()` |

## 4. 踩坑（照抄代码前必读）

1. **three r168 的逐实例色不需要 `material.vertexColors`**：片元前缀在 `parameters.instancingColor`
   成立时会自动 `#define USE_COLOR`（`vendor/three.module.js:20050`）。少写这一条不会报错，只是
   所有实例悄悄变成同一个颜色 —— 很难查。
2. **尾迹别用「上一帧→这一帧」的线段**：72fps 下 15m/s 的子弹一帧只走 0.2m，看起来是一颗孤零零的球。
   按固定长度从弹头向后拖，长度才与帧率无关。
3. **曳光必须在帧末取位**：`game.js` 的帧内顺序是 `_updateExplosions → … → _updatePlaying(bullets.update)`，
   如果放在前半段取位，尾迹会比弹头滞后整整一帧（0.2m 的可见错位）。
4. **枪口焰不要加 `PointLight`**：动态光源会让全场景 PBR 材质重新编译/重算，收益远小于代价。
5. **精英波时间窗不能只改时长**：见 §1.2 的说明 —— 改了时长不同步前移，后期精英波等于被删掉。
6. **`waves.js` 是 CRLF 文件**：改它的脚本必须「读入归一成 LF → 打补丁 → 写回前转回 CRLF」，
   否则整文件行尾翻转（`git diff` 会变成「整文件重写」）。

## 5. 验证方法

### 5.1 自动化（`npm test`）

`tests/stage2.test.mjs`（13 例）：

- 关卡时长表：1~6=40 / 7~10=50 / 13 起=60 / 机制与 Boss 关=基准 / 未知关=基准
- 精英波前移：比例 = 40/60、60s 关不动（`deepEqual` 原值）、**三期都落在关卡结束之前**（含反证）
- 曳光：容量封顶、`clear()` 归零、尾迹中点与长轴拉伸方向、敌方三色齐备
- 火花：爆发数量在区间内、池满不突破上限、**不受重力**、寿命到期全部回池
- 碎片：受重力、颜色 = 传入 tint、未给色回落兜底、精英倍率放大
- `ENABLED:false` → 零创建；枪口焰闪现/自动熄灭/槽位轮转；门面 `clear()` 全清

### 5.2 现场（头显内）

| 判据 | 期望 |
|---|---|
| 开枪 | 弹道上有金色曳光拖尾；枪口有一点闪光（不是常亮） |
| 打中 | 弹着点溅出暖金光点，~0.14s 消失 |
| 打死 | 按敌种颜色炸出碎片（幽灵白灰 / 章鱼紫 / 心形青…），碎片会往下掉 |
| 幽灵 / 章鱼开火 | 鬼火带紫色曳光、墨汁带暗紫曳光（近黑，提亮过） |
| 1~6 关 | 倒计时从 **40** 起；精英波明显更早出现，后期精英波能打到 |
| 7~10 关 | 倒计时从 **50** 起 |
| 13 关之后 | 倒计时 60 起、精英波时机与改动前**完全一致** |
| 性能 | `Frame p95` / `renderer.calls` 与改前对比：calls 增幅 ≤4，fps 不掉档 |

> 快速到某关：平台点「启动游戏」拉起页面后，头显浏览器地址加 `&gate=0&devui=1`
> 用右侧选关面板跳到目标关（正式包只藏了调试入口，参数仍可用，见 05 号文档）。
