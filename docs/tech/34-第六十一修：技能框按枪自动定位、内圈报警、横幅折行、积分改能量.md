## 0. 现场稿（原样存档）

```
1-枪支右边提示框，没有往枪的中间移，反而是往上方移了，攻击后面就直接跟数字了，
  没有加冒号区分，同时颜色字体也是一样，需要做出颜色区分，同理其它的参数也一样。
2-小怪靠近场地红色闪烁时，会出现滴滴滴的急促音，用来提醒玩家赶紧清理，如果有多个靠近的，
  按区域前后左右，每个区域只允许一个最靠近玩家的发出报警声，每个间隔2秒
  （目的是防止到处都是滴滴滴，让玩家分不清同时也感到厌烦，如果你有更好的方式也可以）。
3-横幅提示有时候超出显示范围了，但是太长玩家不容易看，是否可以分成两行。
  另外，因为商店币已经代表钱了，可以将积分的文字换成能量这样玩家不容易混淆。
```

## 1. 目标与判据

| 现场诉求 | 做法 | 判据（怎么算做到了） |
|---|---|---|
| 提示框要落在**枪身中间**，不是枪上方 | 位置不再手填 grip 坐标，改**量枪模型包围盒 → 沿枪管轴取中点 → 侧偏** | 面板与枪管轴同高；模型没就绪才回落 `POSITION` |
| 标签与数值要**分得清** | 新增 `_kv()`：标签灰蓝常规字重、数值各自亮色粗体、中间一个中文冒号 | 四行断言：`消耗：/ 攻击力：/ 弹道：/ 射速：/ 充能：` 各自成段且有独立颜色 |
| 怪逼近要**听得到**提醒 | 新增 `DANGER_ALARM` + `game/dangerAlarm.js` + `audio.playDangerAlarm()` | 进圈闪红 ⇒ 每 2s 一记「滴滴」，且**一帧最多一声** |
| 一片滴滴滴要**别吵、别分不清** | 四分区 + **每区只让最近的那只**发声 + **全场一个节拍** + **方位轮转** | 4 只怪同时贴脸 ⇒ 4 个节拍各响一次，不会同帧叠 4 声 |
| 横幅太长**顶出卡片** | `wrapBannerText()`：先折 ≤2 行，仍放不下才降字号 | 折行后不丢字、每行都 ≤ 可用宽度；极端长文案字号有下限 |
| 「积分」与「商店币」**混淆** | 面向玩家的文案统一改叫「能量」（商店币不动） | `分数`/`积分` 在 HUD 与日志里都读作「能量」 |

## 2. 原理

### 2.1 为什么手填 grip 坐标必然把面板顶到枪上方

第五十九修把提示框从「右手腕」挪到「枪身左侧」，用的是 `SKILL_HINT.POSITION = { x: -0.119, y: -0.045, z: -0.2 }`
—— 一组**手填的 grip 本地坐标**。问题在于枪本体不在 grip 原点：

```
GUN.POSITION = { x: …, y: -0.25, z: … }   // 整把枪在手腕「下方 25cm」
```

`POSITION.y = -0.045` 只往下压了 4.5cm，而枪心在 -25cm ⇒ 面板必然停在**枪的上方 20cm 处**。
现场描述「没有往枪的中间移，反而是往上方移了」就是这 20cm。

结论：**只要手填 grip 坐标，枪一移动/换模型就又会飘**。改成「相对枪自己」量：

```
量枪模型在持有层(root)空间的包围盒 → 取最长轴当枪管轴 → 沿轴取 ALONG 处（0.5 = 枪身正中）
→ 再沿「玩家左手边」偏 (radius + LATERAL_GAP) → 最后用 holder.matrix 把枪空间坐标换回 grip 空间
```

### 2.2 为什么报警要「分区 + 每区取最近 + 全场一个节拍 + 轮转」

如果按「每只进圈的怪都响一声」写，现场就是**一帧 4 声**（四个方向同时逼近时）：分不清方向、听久了烦。
所以叠了四层约束（缺一层就退化）：

1. **候选 = 已经进圈的基础怪**。判据与头顶「爆」字**同源**（`isBombMarkTarget` + `BOMB_LABEL.INNER_RADIUS`）
   ⇒ **看得见闪红 ⇔ 听得到滴滴**，不会出现「看得见却没声」或「有声却没看到怪」。
2. **按玩家前向分四区，每区只留最靠近玩家的那一只** ⇒ 同区再多怪也只出一个代表。
3. **全场共用一个 `INTERVAL` 节拍**（不是每区各响一次）⇒ 同一帧最多一声。
4. **区域轮转**（优先「最久没响过」的方向）⇒ 听感是「前 → 右 → 后 → 左」而不是一直同一个方向，
   新出现威胁的方向会**立刻被照顾到**（它的 `_last` 还是 `-Infinity`，最久没响）。

左右方向由 `SECTOR_PAN` 的**立体声声像**带出来，越近音高越高（`PITCH_NEAR`）—— 听感上「更尖 = 更近」。

### 2.3 为什么折行要按**字符**找断点

横幅文案是中文，**没有空格**，按词折行不成立。于是按字符扫描：前缀必须放得下（前缀超宽则再往后只会更宽，直接 break），
在可行断点里挑「两行宽度最接近」的那个（避免「一行挤爆、一行空着」）。找不到可行断点就**原样返回**，
交给外层「整体降字号」循环兜底 —— 所以任何文案都不会死循环，也不会顶出卡片。

### 2.4 为什么「积分」必须改名「能量」

商店关（第 3/9/15 关）引入了**商店币**，而技能资源一直叫「积分」—— 两者在 HUD 上并排出现时，
玩家分不清「哪个是打怪涨的、哪个是买东西的花的」。商店币已经代表钱了，所以：

- **商店币**（`shopCoin`）不动，继续叫「商店币」；
- **技能资源**（`score` / `skillCost` / `SCORE_CAP`）的**所有面向玩家文案**改叫「能量」；
- **变量名一律不动**（`score` / `skillCost` / `SCORE_CAP` / `_addScore`…），避免大范围改名引入风险。

## 3. 关键实现

### 3.1 面板自动定位（`src/vr/skillHint.js` + `src/vr/rightGun.js`）

```js
placeOnGun(model, holder)     // 返回 false = 模型没就绪，调用方继续用 SKILL_HINT.POSITION 兜底
```

- 包围盒/枪管轴算法**复用** `src/vr/streakCounter.js` 的 `modelBoxInParentSpace()` + `barrelMount()`
  （第四十二修给连杀计数写的，同一套「最长轴 = 枪管轴、朝 -Z 的那端 = 枪口」）；
- 结果按 `MOUNT` 的 `ALONG / SIDE / LATERAL_GAP / UP` 计算，`_mountKey` 记忆 ⇒ **只算一次**，
  改 `userConfig` 热调会重新算；
- `model` 或 `MOUNT` 变了才重量包围盒（模型是异步加载的，首帧必然没有 → 自动落到兜底分支）；
- **只改 position，不动 rotation**（沿用构造里的 `ROTATION = -90°`）；
- `holder.updateMatrix()` 后再 `applyMatrix4` —— 枪每帧带着后坐力/换手在动，坐标必须当帧换算；
- `SKILL_HINT.DEBUG = true` 时**整段跳过**，让 `debugMove()` 的摇杆微调说了算。

`rightGun.update()` 里的接线：

```js
this.skillHint.attach(anchor);
if (!SKILL_HINT.DEBUG) {
  if (!this.skillHint.placeOnGun(this.model, this.root)) {
    const P0 = SKILL_HINT.POSITION;
    this.skillHint.mesh.position.set(P0.x, P0.y, P0.z);
  }
}
```

### 3.2 标签/数值双色（`skillHint._kv()`）

```
标签  '消耗：' / '攻击力：' / '弹道：' / '射速：' / '充能：'  → LABEL_TEXT（#93a7c2，常规字重）
数值  各自亮色 + 粗体 → VALUE_ATK 橙 / VALUE_SHOT 绿 / VALUE_RATE 蓝 / 充能 白（加速期转金）
```

右侧那一栏（弹道 / 充能）要贴右边界，所以 `_kv()` **先各量一次宽再从左往右画**（`align='right'` 时 `sx = x - total`）。
第 2 行的状态文字顺带把「积分不足 · 现有 N」改成「能量不足 · 现有 N」。

### 3.3 报警规则（`src/game/dangerAlarm.js`，纯函数 / 无 THREE 依赖）

```js
sectorOf(dx, dz, fx, fz, wedgeDeg)   // → 0 前 / 1 右 / 2 后 / 3 左；-1 = 退化输入
class DangerAlarm { update(dt, player, list, now) }   // → null 或 {sector,name,index,dist,freq,gain,pan,count}
```

- **手性**：`deg = -atan2(cross, dot)` 后归一化到 `[0,360)`。取负是必须的 ——
  直接 `atan2` 得到的角是**顺时针为正**（对前向而言 = 转向玩家左手边），取负之后 +90° 才是玩家**右手边**。
  自检：面朝 -Z（`f = (0,-1)`）时怪在 `(-1,0)` → 270° → 左扇区；怪在 `(1,0)` → 90° → 右扇区。
- **分区宽度**：前 ±`WEDGE_DEG`，剩余 `360 - 2×WEDGE` 平摊给 右 / 后 / 左（默认 45° ⇒ 四个 90° 扇区）。
- **危险圈半径走 `player.inner`**（`game` 传 `BOMB_LABEL.INNER_RADIUS`）⇒ 半径**只有一个事实来源**，
  不会出现「爆字圈」与「报警圈」各写一份常量然后走偏。

### 3.4 报警接线（`game._updateDangerAlarm`）

```js
this.balloons.update(dt, pp, this.world.camera);
this._updateDangerAlarm(dt, pp);          // 普通关 + Boss 关都会走到这里（商店关/激光关在前面已 return）
```

- 筛怪：`isBombMarkTarget(b) && b.mesh.visible && hypot(p.x, p.z) <= BOMB_LABEL.INNER_RADIUS`
  （候选数组 `this._alarmList` 复用，每帧 `length = 0` 重填，**零 GC**）；
- 朝向：`camera.getWorldDirection(this._fwd)` 给的是 **+Z**，必须取反才是玩家真实面朝方向；
- 切关复位：`_loadLevel()` 里 `this.dangerAlarm?.reset()` ⇒ 节拍与轮转记账不跨关。

### 3.5 报警音（`audio.playDangerAlarm`）

`square` 振荡器 + 极短包络（`PULSE_DUR 0.055s`）× `PULSES 2` 声，走 `sfxBus`（与枪声同总线、同 `SFX_GAIN`）。
左右声像用 `createStereoPanner()`，**可选 API** ⇒ `typeof` + `try/catch` 兜底，拿不到就居中，不影响发声。

### 3.6 横幅折行（`warningBanner.wrapBannerText` + `_fillLines`）

- `_drawWarn`：`maxW = CANVAS_W - 2×(96+52+16) = 696`（左右各一个警示三角：中心 96 ± 52 + 余量），
  `size 88 → minSize 46`；
- `_drawHeal`：`maxW = CANVAS_W - 240 = 784`（左侧十字占住 cx=108 ± 34），文字仍居中于 `CANVAS_W/2 + 40`；
- `_fillLines()`：单行落在 `cy = CANVAS_H/2 + 4`（**保持第四十二修以来的老位置**，老断言不受影响），
  两行则以 `cy` 为中心上下各让 `size × 1.05 / 2`；
- `_drawTitle` **不动**（关卡名短、且早就有自己的降字号循环）。

### 3.7 「积分」→「能量」文案清单

| 位置 | 改成 |
|---|---|
| `ui/hud.js` 顶栏 | `分数 N` → `能量 N` |
| `vr/wrist-ui.js` 两处 | `分数 :` → `能量 :` |
| `vr/skillHint.js` | 第 2 行「能量不足」+ `scatter` 技能名「能量散射」 |
| `game/game.js` log | `测试 +N 能量` / `能量不足（需N）` / `能量散射！消耗N能量…` / `第3关奖励：+500 能量` |
| HUD 技能名（`hud.setSkill`） | `'积分散射'` → `'能量散射'` |
| 注释 | `constants.js` / `userConfig.js` / `player.js` / `input.js` / `enemies.js` / `tutorial.js` / `waves.js` |

**不动**：`score` / `skillCost` / `SCORE_CAP` 等变量名，`商店币`（`shopCoin`），
以及 `core/carpet.js` 的「Verlet 积分」（那是数值积分，不是货币）。

## 5. 踩坑

1. **手填 grip 坐标修不好位置问题**。第一次改抱怨「往上移」，真因不是数值不对，而是**参照系**不对
   （枪在手腕下方 25cm）。换参照系（枪自己的包围盒）之后，`MOUNT` 的四个键才有意义。
2. **左右会搞反**。`atan2` 得到的是「顺时针为正」，而现场听到的左右要按玩家视角 ——
   必须在分区前取负；单测用「面朝 -Z 时 +X 是右手边」「面朝 +Z 时反过来」两向锁死。
3. **同一个信息别画两遍**。第 2 行状态文字与「爆」字用**同一个** `INNER_RADIUS` 判据，
   才能保证「看得见闪红 ⇔ 听得到滴滴」；半径走 `player.inner` 传递，不在两个模块各写一份常量。
4. **自动替换「积分 → 能量」会误伤**。`core/carpet.js` 的「Verlet 积分」是数值积分；
   批量替换时必须**排除该文件**，并且不要把变量名（`score`/`skillCost`）一起换掉。
5. **折行不能只改字号**。原来单行固定 88px、没有自适应，长文案直接顶出卡片；
   现在的顺序是「**先折行、再降字号**」，且老断言的单行基线 `CANVAS_H/2 + 4` 保持不变。
6. **测试断言会跟着文案走**。`tests/stage3.test.mjs` 原来断言的是 `'攻击力 12'`（无冒号、无分色），
   分色分字之后必须改成「标签段 + 数值段」两段断言。

  4. HUD / 腕表上读到的是「能量」，商店关仍是「商店币」。
