# 第七十六修：商店侧列可视角度与旧模块缓存清理

## 现场反馈

第 3 关商店仍出现「左侧道具区像被铁甲兵顶掉、右侧少治疗术士 / 多出 Boss 卡」的描述；上一修已经确认名单数据正确，因此这次继续拆「看到的内容」而不是只查数组。

## 根因分析

### 1. 名单没有错，错在四张卡没有同时进入视野

上一版侧列参数为：

```text
ITEM_X = PREVIEW_X = ±1.75
ITEM_DZ = PREVIEW_DZ = 1.15
```

四张卡沿 Z 的中心是 `-1.725 / -0.575 / +0.575 / +1.725`。玩家站在场地中心时：

- 正前方只能看到每列最靠前的一张；
- 向右约 75° 时，最靠后的脸谱 Boss 仍在视线边缘之外；
- 必须转到接近 90°，四张预告才完整同屏。

因此现场很容易先看到「铁甲兵 + 盾甲兵」，再把后面的治疗术士 / Boss 理解为缺卡；左右两侧又是对称列，转头不完整时会进一步放大“串位”的错觉。实际 `ShopDraft.preview` 一直是：

```text
铁甲兵 / 盾甲兵 / 治疗术士 / 脸谱 Boss
```

### 2. 新响应的 no-store 不会自动清掉旧响应的缓存

上一修给静态资源加了 `Cache-Control: no-store`，但这是**响应级**约束：升级前已经缓存在 PICO / Quest 浏览器里的同名 ES Module 仍可能被直接复用。只加 no-store 不能保证把旧缓存驱逐掉。

## 修复

### 1. 侧列收拢到 75°~90° 可视区

`constants.js` 与 `userConfig.js` 同步改为：

```text
ITEM_X    = -1.90
PREVIEW_X = +1.90
ITEM_DZ   = 0.90
PREVIEW_DZ= 0.90
```

- 仍在飞毯 `|X| < 2.0` 范围内，离边缘留 0.10m；
- 卡宽 0.8m，间距 0.90m，卡间留 0.10m，不会贴成一张；
- 绕 Z=0 对称的前提不变；
- 第 3 关四张预告在向右 90° 时完整同屏，75° 时仅最远一张进入边缘。

### 2. 顶层文档发 Clear-Site-Data

`GameServer.java` 在 `index.html` 的响应上增加：

```text
Clear-Site-Data: "cache"
```

它会在页面加载时清掉该 localhost origin 的 HTTP 缓存，确保旧 `eliteBrief.js` / `userConfig.js` 不会跨越 APK 升级继续生效。只清 cache，不动 localStorage / 玩家设置。

### 3. 测试锁住可视条件

`tests/shop.test.mjs` 新增断言：

- 4 张预告在向右 75° 视线的 ±55° 内；
- 预告 / 道具卡间距至少 8cm；
- 侧列离飞毯边缘至少 8cm。
