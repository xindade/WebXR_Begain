# 第七十五修：商店配置缓存与预告名单自检

## 现场反馈

第 3 关商店左侧道具区的「刷新道具」位置出现铁甲兵；右侧只剩铁甲兵、盾甲兵与两张 Boss 卡，治疗术士缺失。

## 核对结果

本轮先在真实浏览器里直接进入第 3 关商店，读取实际构建出来的 `ShopDraft`：

```text
左侧：3 个道具槽 + 刷新道具
右侧：铁甲兵 / 盾甲兵 / 治疗术士 / 脸谱 Boss
位置：x=1.75，z=-1.72 / -0.57 / +0.57 / +1.72（绕场地中心对称）
```

本机源码、服务器清单 `1.0.0` 下发的 `src/content/eliteBrief.js`、APK 内 `assets/game` 的副本三者 sha256 一致，均为 `d7bf3955…`。因此不是当前版本的名单或排版错误，而是测试机仍在使用旧模块/旧覆盖层的高风险状态。

## 修复

### 1. 静态资源禁止缓存

`GameServer.java` 对配置覆盖层和 APK 内静态资源统一加：

```text
Cache-Control: no-store, no-cache, must-revalidate, max-age=0
Pragma: no-cache
Expires: 0
```

避免同名 ES Module（尤其 `src/content/eliteBrief.js`）被头显 WebView 的磁盘缓存复用：文件已换新，页面却继续执行上一局的旧模块。

### 2. 进店留痕实际名单

`game._enterShop()` 现在会写入：

```text
第 3 关 · 商店关：……；右手边精英预告 4 张：铁甲兵 / 盾甲兵 / 治疗术士 / 脸谱 Boss
```

下次若再出现异常，从留痕即可区分「服务端下发错」还是「渲染/缓存错」，不用再靠口头描述猜。

### 3. 整店集成测试

新增一条 `ShopDraft` 级测试，锁定：

- 左手列固定为 3 个道具槽 + 1 个刷新气球；
- 右手列固定为第 3 关的四张预告，顺序逐字一致；
- 左右列 X 不串位，预告列沿 Z 对称且不重叠。
