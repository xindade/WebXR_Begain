## 0. 一句话

现场五条反馈里，**三条的根因不在表现层，而在「字段 / 接线」**：

| # | 现场说法 | 真根因 |
|---|---|---|
| 4 | 「18 关中激光阶段的 Boss，无法被打中」 | 命中代理**借用了 `basic` 类型** —— `basic` 有 GLB 模型、又在 `DEPTH_SPRITE_TYPES` 白名单里 ⇒ 模型异步到位时 `balloonModels` 把 `hitRadius` 改写成「按立绘取景留边折算」的值，`game._collide` 还改走**朝相机的薄板**判定（厚 `2×HIT_SLAB_DEPTH = 0.8 m`）⇒ 30 m 外的 Boss 只剩约 **1.7 m 的薄片** |
| 2 | 「治疗术士有飞向精英怪的加号，但是精英怪血量没有往上加」 | `hp` 是**裸字段**，血条**只在 `takeDamage` 里刷过**；回血路径改完 `hp` 不刷血条 ⇒ 现场看到的血条纹丝不动，等价于「根本没回血」 |
| 3 | 「龙族宝箱受击没有反馈」 | 宝箱**不是气球、不进 `_collide` 的气球循环** —— 火花 / 命中音 / 箱体压一下全都没人做 |
| 1 | 「玻璃格子现在更多数字标号不见了」 | 编号板是**低头掠射角**看的：`NUM_SIZE 0.5` 的小板子走 mipmap，远处几排被平均成一团灰；淡青玻璃 + 白字的对比度也不够 |
| 5 | 远程三兄弟（忍者 / 幽灵 / 章鱼）的血量与体型 | 原来普通精英一律 `sizeMul:1` + 固定 `ELITE_BASE_HP`，Boss 关召唤走敌种原生血量；现按现场口径**分两档** |

## 1. 玻璃编号（第 9 关）：不是「没生成」，是「看不清」

上一轮（第五十修）已把编号画布 128→256、字号 80→150、`NUM_Y_OFFSET` 0.06→0.12，
现场回报**仍然**「上次只有一个 15 看不见，这次更多了」。这排除了「结构上没生成」：

- 32 格 → 32 个 `numMesh`、32 张不同纹理、`_build()` 里显式 `visible = true`（结构排查全正常）；
- ⇒ 只剩**可见性 / 对比度**这一条路。

真正的机理是**掠射角 + mipmap**：玩家站着（眼高 ~1.6 m）低头看地上的编号板（板面高 0.23 m），
视线几乎与板面平行。这种角度下屏幕像素对纹理的采样是极度**纵向压缩**的，
开 mipmap 时 three 会挑一个很高的 mip 层 —— 数字直接被平均成一团灰。
板子越小（`NUM_SIZE 0.5`）、越远（第 7、8 排），越先糊掉，所以现场看到的是「一部分号没了」。

本轮四条一起上（`glassGrid.numTexture`）：

1. `GRID.NUM_SIZE` **0.5 → 0.78**（≈ 格子的 81%，不重叠）：屏幕上的像素多了；
2. 画布 256、字号 **150 → 190**，并加**圆角深色底板** + **深色描边**（`makeTextTexture` 新增 `bgRadius` / `stroke` / `strokeW`）：
   底板把「这里有编号」和淡青玻璃彻底分开，玻璃再亮也不会把白字冲没；
3. **关 mipmap**：`minFilter = LinearFilter` + `generateMipmaps = false`（这才是「更多标号消失」的直接原因），
   配 `anisotropy = 8` 压住关掉 mipmap 之后必然出现的闪烁；
4. 渲染次序天然正确（编号 `renderOrder = 2` > 玻璃 `0`）⇒ 编号永远画在玻璃**之后**，
   不会被玻璃那 55% 的透明度洗掉。

> 若现场**仍然**有格子读不出数字，下一步把编号从「平躺的平面」改成**朝相机的 Sprite**（`_makeNumMesh` 一处），
> 代价是低头时数字不再随格面倾斜、沉浸感略降，属于最后手段。

## 2. 治疗术士：加号到了、血条不涨（hp 是裸字段）

`Balloon.hp` 是个**裸字段**，血条只在扣血路径里刷过：

```js
// 旧实现：只有 takeDamage 里那一次 sprite 缩放
this.hp -= final;
this._hpFg.scale.x = this.hp / this.maxHp;
this._hpFg.position.x = -((1 - k) * this.healthBarRadius);
this._hpFg.material.color.setHSL(0.33 * k, 0.7, 0.5);
```

回血路径（`BalloonManager._applyHealAura` → `t.hp = Math.min(t.maxHp, t.hp + heal)`）改完 `hp` 就结束了，
血条还停在「被打空一半」的长度 ⇒ 现场看到的就是「没回血」。

修法：把那段公式抽成 `Balloon.refreshHealthBar()`，**凡是改 `hp` 的地方都调它**：

| 调用点 | 位置 |
|---|---|
| 扣血 | `takeDamage()` |
| 血条（光环型，`healAura`） | `_applyHealAura` 的光环分支 |
| 粉色加号（脉冲型） | `_applyHealAura` 的脉冲分支 |

以后再出现「换了血 / 复活 / 吸血」之类的新路径，也必须调 `refreshHealthBar()`，别再各写一份公式。

## 3. 龙族宝箱受击：它不在气球的受击循环里

宝箱（`DragonChest`）是第 12 关独有的一个 `THREE.Group`，**不是 `Balloon`**：

- `game._collide` 的气球循环只遍历 `balloons.list` ⇒ 子弹穿过宝箱既不消耗也不给反馈；
- `_pointSegDistSq` 那种「子弹线段 vs 点」的判定已经在别处用过，直接复用。

新增 `game._chestHitTest()`（在 `_updateDragonChest` 开头调用），**只认计数窗口期**：

```js
if (!c || !c.counting) return;                    // 窗口一过箱子就化光点飞走，不该再吸子弹
if (_pointSegDistSq(center, b.prevPos, b.pos) >= r * r) continue;
this.bullets.release(b);                          // 消耗子弹
c.punch();                                        // 箱体压一下
this.fx?.spark(b.pos, DRAGON_CHEST.HIT_SPARK);    // 火花
this.audio?.playHit();                            // 命中音
this._pulseHaptic('HIT');                         // 手柄震动
```

「压一下」的表现放在 `DragonChest` 自己身上（`punch()` 把 `_punch` 拉满，`update()` 里按 `PUNCH_DECAY` 衰减）：
横向鼓、纵向扁，回弹到 0 时**精确复位** `set(1, 1, 1)`（不做精确复位会残留一个歪掉的箱子）。

## 4. ★ 激光阶段打不中 Boss（最容易再踩的一条）

### 4.1 机理

第 18 关的魔术师 Boss 模型是自己挂的，命中靶子是一个**代理气球**（`bossMagician._spawnProxy`）。
它原来借用了 `ENEMY_TYPES.basic`，而 `basic` 恰好是最「重」的一类：

| `basic` 的属性 | 后果 |
|---|---|
| `model: 'Model/基础怪.glb'` | GLB 异步加载完成后，`balloonModels` 会给它换成**立绘 / 模型**外观 |
| `∈ DEPTH_SPRITE_TYPES` | 换立绘时 `balloon.hitRadius = effectiveRadius × tune.scale × captureFrameFit(radius) × DEPTH_SPRITE_HIT_MUL` —— 「按**可见角色**取景留边折算」的值，与 Boss 真实体型无关 |
| `∈ DEPTH_SPRITE_TYPES`（第二重） | `game._collide` 对白名单类型改走**薄板判定**：宽高 = 半径、厚 = `2 × SHOOT.HIT_SLAB_DEPTH = 0.8 m` |

`_applyRadius()` 在开场时明明把 `hitRadius` 设成了「随身高缩放」的 Boss 半径，
但**模型加载是异步的** —— 它在之后才把这两个字段一起改写掉。

再叠上射程：`SHOOT.BULLET_LIFE 2 s × BULLET_SPEED 15 = 30 m`，而 Boss 站的位置正是 **30 m**
（`MAGICIAN_BOSS.INTRO.POS`）。⇒ 玩家子弹在射程**极限**上要穿过一个约 **1.7 m 的薄片**，
现场表现就是「激光阶段的 Boss 怎么打都打不中」。

### 4.2 修法

新增专用类型 `ENEMY_TYPES.bossProxy`：

```js
bossProxy: {
  id: 'bossProxy', name: 'Boss代理',
  hp: 100, speed: 0, radius: 1.0, score: 0,
  behavior: 'basic', selfDamage: 0,
  noPlaceholder: true, noHealthBar: true, plainColor: 0xffffff,
  // 注意：既没有 model，也不在 DEPTH_SPRITE_TYPES 里
}
```

`bossMagician._spawnProxy` 的 `this.spawn('basic', ...)` → `this.spawn('bossProxy', ...)`。
半径从此**完全由 `_applyRadius()` 说了算**（开场小 → 变大后大），没有任何异步路径会再改写它。

> ⚠ 结论写进规矩：**任何「只做命中靶子」的代理气球，都必须用一个「没有 `model`、且不在 `DEPTH_SPRITE_TYPES` 里」的类型。**
> 借用 `basic` / `ninja` / `octopus` 这类「正常怪」当代理，一定会被上面两条改写规则打回来。
> 单测 `tests/hitbox-heal-ranged.test.mjs` 用 `basic` 当对照组把这条钉住了。

## 5. 远程三兄弟（忍者 / 幽灵 / 章鱼）：血量与体型分两档

现场口径：

> 「忍者，幽灵，章鱼在非 boss 模式，体型放大两倍。章鱼也改成在圈外攻击不近身，
> 这三个远程怪，Boss 阶段血量为 DPS×10 + 默认血量，非 Boss 阶段血量为 DPS×2 + 默认血量。」

| 场景 | 血量 | 体型 |
|---|---|---|
| **Boss 关**（第 6 / 12 / 18 关召唤池） | `ELITE_BASE_HP[型] + DPS × 10` | 不覆盖 → 退回敌种自带 `scale`（3） |
| **非 Boss 关** | `ELITE_BASE_HP[型] + DPS × 2` | `sizeMul: 2` |

口径只有一份：`WaveManager.rangedHpOpts(type)`，两处调用 ——

1. `waves._eliteOpts()` 的**普通精英**分支（`!climax`）；
2. `bossMagician._spawnMinion()`（Boss 关召唤池）。

其余普通精英（铁甲兵 / 盾甲兵 / 治疗术士）**不动**，仍是 `sizeMul:1` + 固定 `ELITE_BASE_HP`
—— 第四十七修踩过的坑：全员 DPS 血量会让中段精英变成「打不动的墙」。

> ⚠ 本轮**写文档时又发现接线断了一处**：`bossMagician` 的守卫写成了 `this.waves.rangedHp`
> （这个属性从未存在，恒为 `undefined`）⇒ Boss 关召唤的远程精英**静默**退回敌种原生血量。
> 已改为 `this.waves.rangedHpOpts ? ... : null`，并加单测
> 「Boss 关召唤的远程精英真的吃到 DPS×10 血量」按三个阶段逐个断言。

章鱼「圈外攻击、不近身」：`Balloon.update()` 的环带夹紧条件
`behavior === 'ninja'` → `behavior === 'ninja' || behavior === 'octopus'`，
把章鱼和忍者一样夹进 `SHURIKEN.RANGE_MIN(10) ~ RANGE_MAX(15)` 的环带内（龙形 Boss 的组成部件 `isDragonPart` 照旧跳过）。
