# 第五十四修：子弹量级放开（弹道 12 · 射速 20/秒 · 池 1000）

> 这是「更多子弹」三步里的**第 1 步**。第 0 步（第五十三修）先把 `_collide` 的命中判定垫平
> （去空转 + 线段 AABB 粗筛，×1.86~×3.5），本修才敢动数值。

## 1. 改了哪些数字

| 位置 | 改前 | 改后 | 为什么 |
| --- | --- | --- | --- |
| `cards.js` → `ATTRIBUTE_STATS.multiShot` | 上限 7 | **12** | 用户指定 |
| `cards.js` → `ATTRIBUTE_STATS.fireRate` | 上限 14 发/秒 | **20** | 用户指定 |
| `constants.SHOOT.BULLET_POOL_SIZE` | 500 | **1000** | 最坏并发 = 20 发/秒 ×（连杀加速 1.5）× 12 弹道 × 存活 2s ≈ **720**，再留散射强化那 100 发瞬时弹 |
| `constants.FX.TRACER.CAPACITY` | 512 | **1024** | 与子弹池**联动**（注释里本来就写着「≥ 子弹池 + 敌方投射物余量」），只改一个是漏 |
| `cards.js` 两张卡的 `desc` 文案 | 上限7 / 上限14 | 上限12 / 上限20 | 卡面写给玩家看 |
| 同上两张卡的 `apply` 封顶值 | 硬编码 `Math.min(7/14, …)` | 读 `ATTRIBUTE_STATS` | 上限从此**只有一处口径**；卡面文案与表的一致性由单测锁 |

渲染侧不需要改：`bullets.js` 是 `InstancedMesh`，1000 发仍是 1 个 draw call +
一次矩阵上传；实例色缓冲在构造时就按 1000 建好（不然首次连杀加速要现场上传一整块缓冲）。

**12 / 20 是天花板，不是常态**：一局约 18 次抽卡，7 种属性卡平分外加技能/回血卡，
实际大概能堆到 6~9 条弹道、8~14 发每秒。池子是按**理论最坏值**配的。

## 2. 扇形角度：12 条弹道「完全铺开」= 总张角 17.06°（半角 8.53°）

改前的扇形是**恒定半角**：偏移序列归一化到 ±1（`t = ts/maxT`），所以弹道加到 12 条
也只是**在原来那 9° 里变密**，张角一点不涨 —— 那样「更多子弹」只是一根更亮的棍子。

改后半角随弹道数增长，到第 `SPREAD_FULL_N` 条时用满 `SPREAD_ANGLE`：

```js
const spread = SHOOT.SPREAD_ANGLE * Math.min(1, (n - 1) / ((SHOOT.SPREAD_FULL_N || 2) - 1));
```

| 弹道数 | 半角 | 总张角 | 相邻间隔 |
| --- | --- | --- | --- |
| 2 | 0.78° | 1.56° | 1.56° |
| 3 | 1.56° | 3.12° | 1.56° |
| 5 | 3.12° | 6.24° | 1.56° |
| **7** | 4.68° | **9.35°** | 1.56° |
| 8 | 5.45° | 10.91° | 1.56° |
| **12** | **8.53°** | **17.06°** | 1.55° |

要点：

- **正中永远有一条精确对准准星的弹道**（`_spreadTs[0] = 0`），这条老保证没动。
- 7 条时 9.35° ≈ 改前的 9.15° ⇒ **中局手感基本没被掀翻**，多出来的宽度是把上限从 7 放到 12 才拿到的。
- 两个旋钮（都在 `userConfig.SHOOT`，可热调）：`SPREAD_ANGLE`（半角上限，默认 0.15）、
  `SPREAD_FULL_N`（用满上限的弹道数，默认 12）。**`SPREAD_FULL_N` 写 2 = 退回恒定半角**（改前行为）。
- ⚠ **别随手把 SPREAD_ANGLE 拉到 0.3**：扇形越宽，打远距离**单体**的有效 DPS 越低，而
  Boss / 末尾精英的血量是按**标称 DPS**（攻击 × 弹道 × 射速，见 `game._playerDPS`）标定的 ——
  铺太开会让精心调过的「打十秒」变成「打十七秒」。真要更铺开，得连血量口径一起算。
- 顺带修掉一个小瑕疵：改前偶数弹道整体**偏右**（归一化把 +1 只给了右边），
  所以「额外子弹+1」的 2 发其实是 0° 和 +4.58°（偏右 4.58°）；现在是 0° 和 +0.78°。
- ⚠ **加弹道 ≠ 打 Boss 更快**：基础小怪是**固定血量** ⇒ 12 条弹道一梭子清一片（爽感落在这里）；
  而 Boss / 末尾精英的血量是按**标称 DPS 现算**的（第四十七修：DPS×8 / DPS×10）⇒
  弹道数涨上去，它们的血也跟着涨，TTK 基本不变 —— 这是既定的构筑口径，不是 bug。

## 3. 测试

`tests/bullet-volume.test.mjs`（11 项）：

- 上限口径：`ATTRIBUTE_STATS` 就是 20 / 12；**每张属性卡的 `desc` 里必须出现表里的上限数字**（防只改代码不改文案）。
- 卡牌 `apply` 连点 30 次不越界（20 / 12），射速卡每次都写回 `input.setFireRate`（真实节流源）。
- 扇形几何：单发=1 条且方向=瞄向；12 条里正中那条精确对准准星；最外侧 = 半角；
  半角随弹道数单调增；12 条时用满 `SPREAD_ANGLE`；相邻间隔 ≈1.55°；7 条 ≈ 改前的 9.15°；
  `SPREAD_FULL_N=2` 退回恒定半角。
- 池子不变量：最坏并发 820 ≤ 1000；`FX.TRACER.CAPACITY ≥ BULLET_POOL_SIZE`；
  1000 个实例真的建出来；池满复用最旧的、`active` 不越 `capacity`。

另修两张老测试的「满级玩家」夹具（原来手写 `fireRate:14 / shotCount:7`，现在从
`ATTRIBUTE_STATS` 推导）—— 否则每次放开上限都要回来改测试，也就测不出「满级判定」跟不跟得上表。

`npm test` = **271 项全绿**（第五十三修后是 260）。

## 4. 发布面（本轮特殊：要动服务器）

- `src/game/player.js`、`src/content/cards.js`、`src/core/constants.js` 改了 ⇒ **必须重打 APK**
  （`powershell -ExecutionPolicy Bypass -File tools\cast-apk\build-apk.ps1`）。
- ⚠ **`src/core/userConfig.js` 在服务器清单里**（`CONFIG_MANIFEST` = `src/content/` 整目录 +
  `src/core/userConfig.js`），而 PC 端 `configBaseOf()` 把 userConfig.js **从清单缓存取**
  （不是从游戏目录）⇒ **不部署服务器，现场拿到的还是旧的 `SPREAD_ANGLE 0.08 / POOL 500`**，
  新数值会被服务器那份整包替换盖回去。
  → 改完必须跑一次 `powershell -ExecutionPolicy Bypass -File tools\deploy-content.ps1`。
- 反过来这也是好处：`SPREAD_ANGLE` / `SPREAD_FULL_N` / `BULLET_POOL_SIZE` 留在 `userConfig` 里，
  以后**从服务器热调**即可生效，不用重新打包。

## 5. 还没做 / 待现场观察

- **追踪道具（第 2 步）没开始**：形态（击杀掉落→飞向玩家 / 场上拾取物）、生效口径（限弹数 / 限时）、
  掉落规则（精英必掉 / 概率 / 指定关卡必出）都还没定；追踪只打算给**中心主弹道**。
- `FX.SPARK.POOL` 仍是 64：一次命中喷 3~5 粒，12 条弹道全中同一只 Boss 时每秒接近千粒 ⇒
  池满会反复复用最旧的实例，火花看起来会「被截断」。真觉得打击感糊了就把 POOL 提到 128
  （仍是 1 个实例池、1 个 draw call，代价很小）。
- 头显实测：最坏 720 发在册时，`_collide` 在开发机上 ≈0.4ms（第五十三修基准 1000 发 × 60 怪 = 0.557ms），
  XR2 要乘几倍 —— 现场需要确认帧率不掉。

## 6. 现场怎么快速验这一步（`?gun=12x20`）

12 条弹道靠抽卡要堆十几关才凑得出来，现场没法验收 ⇒ 加了个调试开关
（与 `?gate=0` / `?vrbtn` 同级：正式包也认，但平台拉起时不会带它，所以正常局不受影响）：

| 网址 | 效果 |
| --- | --- |
| `http://127.0.0.1:8123/?gun=12x20` | 开局就是 12 条弹道 × 20 发每秒 |
| `?gun=8` | 只改弹道（射速照旧按卡牌成长） |
| `?gun=x20` | 只改射速 |

- 数值一律**夹到卡池上限**（`ATTRIBUTE_STATS`，即 12 / 20），不给超越合法构筑的数字。
- 生效点在 `main.js` 的 `startGame()` 末尾（`game.start` 会先 `player.reset` 复位属性）；
  解析器是纯函数 `src/core/gunDebug.js` 的 `parseGunDebug()`，带单测。
- **在 PC 上开桌面预览（`127.0.0.1:8123/?gun=12x20`）就能看扇形**，不必进头显：左键持续射击，
  看 12 条弹道铺开的宽度、曳光密度与连射帧率。
- PC 端 EXE 的 `:8443` 自第二十二修起**不再托管游戏页**（头显浏览器直连整站已停用），开 `:8443/?gun=...` 只会拿到 404；桌面预览一律走上面的本地静态服务。
- 验收完删掉参数即可，不用改代码也不用重打包。
