# 第八十修：商店卡面串图（精英/道具混排）与刷新升起

日期：2026-10-18

## 现场症状

- 商店左列（道具）里出现精英卡面，右侧预告列也会重复同一张 Boss 卡；整张卡（含标题、说明、立绘）一起错，不是单纯的图错位。
- 清头显浏览器缓存、重下发覆盖层后仍然复现。

## 先排除的：数据与坐标都是对的

用仓库源码 + 头显覆盖层里的 `eliteBrief.js` / `userConfig.js` 离线构造 `ShopDraft`，第 3 关输出：

```text
道具列  x=-1.90  z=-1.35 / -0.45 / 0.45 / 1.35   （3 道具 + 刷新）
预告列  x=+1.90  z=-1.35 / -0.45 / 0.45 / 1.35   （铁甲兵 / 盾甲兵 / 治疗术士 / 脸谱 Boss）
每张卡的 CanvasTexture UUID 互不相同（dupTex=0）
```

同时核对：头显实际安装的 APK（SHA-256）、包内 `shop.js` / `constants.js` / `userConfig.js`、头显 `files/game-overlay` 的三份关键文件，全部与仓库一致。因此**不是名单、不是坐标、不是旧覆盖层**。

## 结论：Pico 的 2D canvas → 纹理上传路径

商店一次进店会连续创建 8 张以上 256×456 的 canvas 贴图。Pico/Chromium 默认把 2D canvas 放 GPU，
`texImage2D` 取快照时在部分驱动上会复用同一块共享表面 ⇒ 后画的卡面覆盖先画的，表现为
「整张卡（含文字）变成另一张」。这解释了为什么只有卡面会串、气球颜色/位置/价格逻辑都正常。

## 修法（三条一起上）

1. **强制 CPU 后备画布**：`cardDraft.js` 的 `makeCardTexture` / `makeBadge` 以及立绘抓帧
   `enemyPortrait.js` 全部改为 `getContext('2d', { willReadFrequently: true })`。
   浏览器会保留软件位图，上传纹理时逐张同步取像素，不再依赖 GPU 快照。
2. **卡面不做 mipmap**：`generateMipmaps = false` + `minFilter = LinearFilter`。
   UI 纹理不需要 mip，关掉后只上传 base level，减少驱动侧复用机会。
3. **刷新不再原地重绘**：刷新道具时整排气球爆开飞走，结算后 `_forceItemRebuild` 销毁重建，
   新卡从下方 0.9m 升起（`CARD_RISE_T=0.38s`）。补位也只让新卡升起，避免“数字跳一下”。

## 现场自检留痕

每次进商店会向 `/api/page/event` 发一条 `shop-cards`：

```json
{ "ev":"shop-cards", "lv":3, "itemX":-1.9, "previewX":1.9,
  "dup":[], "rows":[["item","item","吸血子弹",-1.9,0.45,"1a2b3c4d"], ...] }
```

判读：

- `itemX=-1.9 / previewX=1.9`、`dup=[]` → JS 数据与贴图都正常，若画面仍串就是设备端渲染；
- `dup` 非空或 X 不对 → 代码层复用/摆位错误，按 rows 直接定位。

## 如果仍然复发的兜底

按现场建议改为**预烘焙**：右侧预告列每店一张合成 PNG（3/9/15 三张），左侧道具卡
按“卡框 + 图标 + 标题 + 说明”烘焙成 7 张静态 PNG，等级/价格改成卡前的小牌子。
这样商店里不再有运行时 canvas 贴图，可彻底绕开设备端上传路径。当前先验证 1~3 条是否已解决。
