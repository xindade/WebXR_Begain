# 14 · 打击感（档1）与伤害数字

> 现场反馈：「游戏的节奏变化、打击感、特效这些可能要再加强一下。」
> 本篇只覆盖**档 1** —— 不改渲染管线、不加粒子、不碰平台链路，纯「音效分层 + 抖动 + 连击 + 手柄震动 + 伤害数字」。
> 档 2（曳光 / 命中火花 / 击杀碎片 / 枪口焰）与档 3（波次编排 / BGM 跟波次）不在本篇，见文末「后续档位」。

## 1. 目标

| # | 问题（改前实测） | 改后 |
|---|---|---|
| 1 | 命中与击杀**共用同一个 `playPop()`**，每次音量/音高完全相同 → 高射速（16 发/秒）下几十发叠成一片「嗡嗡」，听不出打中了什么 | 命中 = 轻 tick；击杀 = 按敌种换音色；每次播放带 ±抖动 |

## 2. 原理

### 2.1 为什么「抖动」是第一优先级

打击感的听觉基础是**每一下都不一样**。真实枪械/打击音的音高与音量天然有 ±5~15% 的随机波动；
代码合成音若是常量，连续播放就退化成周期信号 —— 人耳会把它听成一条连续的噪声带，而不是一记记的打击。

所以 `_jitter(v, amt)` 是最便宜、收益最大的一味：**一行代码，改的是「能不能听出节奏」这件事**。

### 2.2 为什么命中音与击杀音必须分开

一个 100 HP 的基础怪，命中 1 次就死 —— 如果命中和击杀同音，玩家永远听不出「这一发打死了」。
分开之后，听觉上就出现了两段式结构：`tick… tick… tick…THUMP`，节奏感自然出现。

### 2.3 为什么击杀音要按敌种分派

幽灵（空灵）、章鱼（湿润）、盾兵（金属）、精英/Boss（低沉重击）在**视觉上本来就不同**，
听觉却完全一致时，玩家的大脑会把它们当成同一种东西 —— 这是「敌人再多也觉得单调」的隐形来源。
分派音色不需要新素材（全部靠波形/频率/时长区分），却能让玩家闭着眼也知道自己在打什么。

### 2.4 伤害数字为什么必须合并

高射速下 16 发/秒 × 多弹道，若每发都弹一个数字：
- 视觉上刷屏，反而看不清；
- 性能上每次都要重绘 canvas + `texture.needsUpdate` 上传纹理 —— 头显 GPU 本来就紧。

因此**同一只怪在 `AGGREGATE_WINDOW`(=0.14s) 内的多次命中合并成一个数字、数值累加**。
这带来两个副作用，都是正向的：

1. 并发上限 = 同时被击中的怪数（而不是子弹数），`POOL=24` 绰绰有余；
2. 对高血量目标（盾兵 300 / 召唤 500 / 精英 / Boss），数字会**累加成一个「伤害计数器」** ——
   高射速压制时看着它一路爬大、颜色一路变红，反而是最直观的反馈。

## 3. 关键实现

### 3.1 音效：`src/vr/audio.js`

| 方法 | 用途 | 配方（`mul` = 连击音高倍率，`vol` = 抖动后的音量） |
|---|---|---|
| `playShoot()` | 开火 | 白噪 0.12s → `lowpass (3000 × _jitter(±20%))` → `(0.25 × 音量抖动) → expRamp(0.001, +0.12)` |
| `playHit()` | 普通命中 | `triangle`，`1500 → 825`（0.06s，均带抖动）→ 音量 `0.16 × 抖动` |
| `playKill(kind, combo)` | 击杀 | 先算 `mul`，再交 `_killVoice` 按 kind 选配方 |
| `_jitter(v, amt)` | 抖动 | `v × (1 + rand(-1,1) × amt)`，默认 `amt = PITCH_JITTER = 0.08` |

**连击升调**：`steps = clamp(combo - MIN_FOR_FEEDBACK + 1, 0, COMBO_MAX_STEP)`，`mul = 1.06^steps`。
即第 1~2 连不变调，第 3 连起每多一连升 6%，最多 +60%（8 级）—— 克制，不会变成滑稽的滑音。

**`_killVoice` 音色表**（`kind` 取自 `balloon.type.id`，精英/Boss/龙优先）：

| kind | 配方 | 听感 |
|---|---|---|
| `basic`（默认） | `square` 200→800（0.15s） | 原 pop |
| `ghost` | `sine` 780→1560 + `sine` 1040→2080（0.40~0.45s） | 空灵长尾 |
| `octopus` | 白噪 0.24s → `lowpass 700` + `sine` 230→85 | 湿润 |
| `ninja` / `eliteKnight` | `triangle` 2400→1300 + `square` 3600→2000 | 金属 ping |
| `shield` | `square` 380→300 + `square` 511→403 + 噪声 `highpass` | 金属敲击 |
| `heart` | `sine` 880→1320 + `sine` 1320→1760 | 明亮上行 |
| `chest`/`treasure`/`orb` | `sine` 1046 / 1318 / 1568 三连 | 金币 |
| `elite` / `boss` | `sawtooth` 160→55 + `square` 240→90 + 噪声爆 | 低沉重击 |
| `dragon` | `sawtooth` 120→48 + 噪声 | 更重 |

高频枪声（`playPop`）**保留未改**：它仍被九宫格命中、龙头死亡连环爆炸等「机制/演出」路径使用。

### 3.2 伤害数字：`src/game/damageNumbers.js`（新增）

- `damageTierIndex(amount)` / `damageColorOf(amount)`：纯函数，`clamp(floor(amount / 100), 0, 6)`。
- 颜色档（由浅到深）：`0xffffff → 0xffe066 → 0xffb347 → 0xff8a33 → 0xff5a1f → 0xff2a12 → 0xd41010`
  - 判据是**红色占比单调递增**，不是红通道递增 —— 最后一档是**更暗**的深红，红通道反而回落。
- 档位 ≥ `BIG_TIER`(4) 时描边改金色，字号每档 +6%，击杀那一击额外 ×1.18。
- 每个池条目自带一张 256×128 canvas；只有数值变化时才 `tex.needsUpdate = true`。
- Sprite `depthTest: false` → 数字永远压在模型之上，不会被敌人挡住（打击感 > 空间正确性）。
- **全池化**：`_obtain()` 池空且未满就新建，池满则回收 `_live[0]`（最旧）。绝不每次命中 `new`。

### 3.3 接线：`src/game/game.js`

| 入口 | 行为 |
|---|---|
| `_damageFeedback(balloon, killed)` | 命中统一入口：弹数字 + （未击杀时才）`playHit()` + `HIT` 震动。击杀那一击**不发命中音**，避免两音同帧糊在一起 |
| `_killFeedback(balloon)` | `_onKilled()` 的**首行**：连击 +1 → 按敌种 `playKill()` → 中/重震动。所有击杀路径（子弹/激光剑/如来神掌/自爆/脸谱子实体/龙部件）自动共享 |
| `_killSoundKind(b)` | 敌人 → 音色键：`isBoss > isDragonPart > isElite > type.id > behavior` |
| `_bumpCombo()` | `WINDOW`(=1.5s) 内连续击杀累加，超时从 1 重新起算；`update()` 里负责过期清零 |
| `_pulseHaptic(channel)` | 四档震动 + 同档 `MIN_GAP`(=0.05s) 节流；`HURT` 双手一起震，其余震右手（持枪手） |
| `this.damageNumbers` | `update()` 每帧推进；`start()` / `toMenu()` / `_restartLevel()` 三处 `clear()` |

`balloons.takeDamage()` 新增 `this._lastDamage` —— 记录**减伤后**的真实伤害（脸谱 Boss 95% 减伤时数字显示的是 5 而不是 100，
这恰好把「打不动」这件事直白地告诉玩家）。无敌/未命中时保持 0，`spawn()` 对 0 直接返回，不产生数字。

### 3.4 震动：`src/vr/input.js`

新增 `pulseHand(hand, intensity, durationMs)` 与 `pulseBothHands(...)`，**双 API 兼容**：

```js
hapticActuators[0].pulse(i, d)                              // 多数浏览器
gamepad.vibrationActuator.playEffect('dual-rumble', {...})  // Chromium 系
```

两种都没有 → 静默返回 `false`。**震动永远不是玩法必需项**，因此全程 `try/catch` 且不抛错、不阻塞。

## 4. 参数表（`src/core/constants.js`，均可在 `src/core/userConfig.js` 热调）

### 4.1 `HIT_FEEDBACK`

| 键 | 默认 | 说明 |
|---|---|---|
| `SOUND.HIT_VOLUME` | 0.16 | 命中音量（原 `playPop` 为 0.3；调大就会重新变糊） |
| `SOUND.KILL_VOLUME` | 0.34 | 击杀音量 |
| `SOUND.PITCH_JITTER` | 0.08 | **每次播放音高 ±8%（改 0 = 关闭抖动，回到改前手感）** |
| `SOUND.VOLUME_JITTER` | 0.15 | 每次播放音量 ±15% |
| `SOUND.COMBO_PITCH_STEP` | 0.06 | 连击每级音高 +6% |
| `SOUND.COMBO_MAX_STEP` | 8 | 连击最多升 8 级（+60%） |
| `COMBO.WINDOW` | 1.5 | 连击窗口(s) |
| `COMBO.MIN_FOR_FEEDBACK` | 3 | 达到几连才开始升调 |
| `HAPTIC.ENABLED` | true | 震动总开关 |
| `HAPTIC.HIT/KILL/ELITE/HURT` | 0.12/0.35/0.60/0.80 | 四档强度（duration 20/45/70/120 ms） |
| `HAPTIC.MIN_GAP` | 0.05 | 同档震动最小间隔(s) |

### 4.2 `DAMAGE_NUMBER`

| 键 | 默认 | 说明 |
|---|---|---|
| `ENABLED` | true | 关掉只影响显示，不影响计分与音效 |
| `STEP` | 100 | **每满 100 伤害加深一档**（想要每 50 一次就改这里） |
| `COLORS` | 7 档 | 数组，写了就整体替换（顺序 = 由浅到深） |
| `BIG_TIER` / `BIG_STROKE` | 4 / `#ffd24a` | 从第 4 档起加金色描边 |
| `SIZE` / `TIER_SCALE_STEP` / `KILL_SCALE` | 0.30 / 0.06 / 1.18 | 世界高度(m) / 每档放大 / 击杀额外放大 |
| `LIFE` / `RISE` / `POP` | 0.75 / 0.9 / 1.35 | 存活秒 / 上浮速度 / 出生瞬间放大 |
| `AGGREGATE_WINDOW` | 0.14 | **同一只怪的合并窗口(s)；调大 = 数字更少更粗，调小 = 更密更快** |
| `POOL` | 24 | 并发上限（超出回收最旧） |

## 5. 踩坑（改之前先看这里）

| 坑 | 说明 |
|---|---|
| **命中音和击杀音同帧叠加会糊** | 若在 `_collide` 里无条件 `playHit()`、`_onKilled` 里再 `playKill()`，击杀那一击会同时出两个音。`_damageFeedback` 因此用 `if (!killed)` 兜住 |
| **深红档的红通道反而更小** | 颜色判据必须用「红色占比」；用「红通道单调递增」写测试一定挂（`0xff2a12` → `0xd41010`） |
| **合并窗口若在每次命中后重置 → 变成无限累积** | 当前实现就是**故意**重置 `e.t`：连续被压制的目标会累加成伤害计数器。若你想要「每次命中一个独立数字」，把 `AGGREGATE_WINDOW` 调到 0（代价：刷屏 + 频繁上传纹理） |
| **`clear()` 必须同时清 `_agg`** | 否则已回收的条目仍挂在 `_agg` 上，`spawn` 会命中的已死条目 |
| **Pico 的震动支持不稳** | `hapticActuators` 在部分机型/浏览器上不存在。**必须**静默降级，否则一次 `TypeError` 就能在命中瞬间打断游戏循环 |
| **`_onKilled` 的递归** | 脸谱 Boss 子实体死亡会递归调用 `_onKilled(boss)`。`_killFeedback` 放在首行 ⇒ 一次递归 = 两声击杀音（子实体 + Boss）。这是**有意**的，听感上是「连炸」；若不想要，加 `if (balloon.isBoss) ...` 之类的过滤 |
| **`document` 桩缺失** | `tests/register.mjs` 的 canvas 桩只支持 `createElement`，**且 `game.js` 在模块加载期就会调 `TextureLoader.load()`**（`buddhaFx.js`）⇒ **不要在测试里 `import game.js`**，只测独立模块（见下） |

## 6. 验证方法

### 6.1 自动化（`npm test`）

`tests/hit-feedback.test.mjs`（11 例）：

- 颜色分档：`99 → 档0`、`100 → 档1`、`200 → 档2`、超限封顶；红色占比单调递增
- 合并窗口内累加（`100 + 100 = 200`、并发恒为 1）；窗口过后重新起算
- 并发封顶 `POOL`，创建的条目数不超过 `POOL`（证明没有无限新建）
- 到期回池隐藏；`clear()` 清空 `_live` 与 `_agg`
- 击杀音色：幽灵=双正弦、章鱼=噪声+低通、盾兵=方波、未知敌种回落基础怪
- 连击升调：起始频率被抬高且幅度克制
- 抖动：`amt=0` 时完全确定；`0.08` 时恒在 ±8% 内
- 震动：`pulse` / `vibrationActuator` 两条路径 + 无硬件静默 + 强度钳制

### 6.2 现场（头显内）

| 判据 | 期望 |
|---|---|
| 打不死的高血量目标（盾兵/精英） | 能明显听到「tick tick tick」逐发区分，而不是一片嗡声 |
| 打死一只 | `tick…THUMP` 两段式；幽灵空灵、章鱼湿润、盾兵金属、精英/Boss 低沉 |
| 快速连杀（>3 连） | 击杀音明显逐级上扬 |
| 手柄 | 命中轻震 / 击杀中震 / 精英重震 / 受伤双手重震（Pico 若无震动即静默，不是 bug） |
| 伤害数字 | 从怪头顶弹出；打 100 → 浅黄，200 → 橙，500+ → 深红+金边 |
| 压制一个高血量目标 | 数字一路累加变大、颜色一路变红 |
| 抽卡 / 死亡重开 / 回菜单 | 场上数字立即清空，无跨关残留 |
