## 2. 正前方「技能 / 强化」也要放大，但「购物完成」不许跟着长

第五十八修把**两列**（道具 / 精英预告）放大 2 倍、「选项卡」放大 1.5 倍，而商店关**正前方那一排**
（技能本体 ×3 + 购物完成）当时是**有意保持原样**的（`CARD_SCALE_FRONT = 1`）。本轮现场要它变大。

关键点：正前方那一排**混着两种卡** —— 三个「技能本体 / 技能强化」+ 一个「购物完成」，而第五十八修
的口径是「购物完成保持原样」。所以**不能**只把 `CARD_SCALE_FRONT` 调大（那会把购物完成一起放大），
必须**逐张取缩放**：

```js
// shop._build()
const front = this._frontEntries();
front.forEach((e, i) => this._addEntry(e, new THREE.Vector3(x0 + i * SHOP.FRONT_SPACING, SHOP.FRONT_Y, SHOP.FRONT_Z), {
  scale: e.kind === 'done' ? SHOP.CARD_SCALE_DONE : SHOP.CARD_SCALE_FRONT,   // ← 逐张
  faceX: 0,
}));
```

另有一条**联动**：卡放大 1.5 倍后，气球（`CARD.BALLOON_HEIGHT × scale`）会抬高 0.35m，而正前方那块
「商店币」牌子又是挂在「气球上方」（`FRONT_Y + BALLOON_HEIGHT × CARD_SCALE_FRONT + BADGE_DY`）——
不处理就会顶到 4.4m（≈34° 仰角，得抬头找）。故 `SHOP.FRONT_Y 2.6 → 2.35` 把整排压回来，牌子高度与
旧版基本齐平（≈4.15m）。

> **记一条**：`holder.scale` 一变，「本地坐标手算成世界坐标」的地方全都要乘 scale —— 本轮这里是
> `balloonY` / `balloonHit` / `bob`（第五十八修已改成集中字段，所以本轮**零改动**自动跟随）。新增卡类
> （如 `kind === 'done'`）时必须走同一套字段，别在手算里写死 `CARD.BALLOON_HEIGHT`。

## 3. 「以场地中心为中心，Z 正负方向均匀放置」：飞毯只有 4m × 8m

**真因**：两列卡的 Z 是「从 `-1.0` 起，每张往后 `-1.15`」单向往后排 ——

| 列 | 张数 | 旧 Z 范围 | 问题 |
|---|---|---|---|
| 道具列（3 道具 + 刷新） | 4 | -1.0 … **-4.45** | 第 4 张已在飞毯外（半深 4.0） |
| 精英预告列 | 5（第 3 关）| -1.0 … **-5.6** | 后 2 张在飞毯外 |
| 精英预告列 | 6（上限）| -1.0 … **-6.75** | 后 3 张在飞毯外 |

而且 X = ±3.0 **整列都在飞毯外**（飞毯宽 = `MOVE.BOUND_X × 2 = 4.0m`，半宽 2.0）。

**修法**：X 收进 `±1.75`；Z 换成**绕场地中心对称**的纯函数排布：

```js
// src/game/shop.js
export function columnZ(zc, dz, i, n) { return zc + (i - (n - 1) / 2) * dz; }
```

| 列 | n | 新 Z 范围（dz = 1.15） | 是否在毯内 |
|---|---|---|---|
| 道具列 | 4 | -1.725 … +1.725 | ✅ |
| 精英预告列 | 5 | -2.3 … +2.3 | ✅ |
| 精英预告列 | 6 | -2.875 … +2.875 | ✅ |

对称是**结构性**的收益：`Σz ≡ 0`、相邻间距恒等于 `dz`、整列长度随张数自动伸缩 —— 卡片张数变化
（3/5/6）时不用改任何常量，也不会偏心。两张列都对称 ⇒ 左右镜像天然成立（`PREVIEW_X = -ITEM_X`）。

**配套**：两块「区域牌子」的 Z 从「第一张卡上方」改成**列中心 Z=0 上方**（`SHOP.ITEM_ZC` / `PREVIEW_ZC`），
否则牌子会跟着第一张卡跑到毯边。

> **记一条**：成列摆放的坐标一旦有「起点 + 序号 × 间距」，就要问一句「张数变化时整列往哪边跑」。
> 单向往一边排 = 张数一多就出界；绕中心对称 = 天然有界。

## 4. 立绘卡文案装不下：先把「几行 / 每行多宽」算清楚

卡面 canvas 固定 **256×456**（`makeCardTexture`），默认 `contain` 缩放 ⇒ **放大卡面不会变清晰度**，
只是把同一张图放大（所以文字同步变大、不模糊）。立绘版式（`opts.portrait`）的竖向预算：

| 元素 | 旧 | 新 |
|---|---|---|
| 图区 | `Y0=22`，`PH=236` → 底边 258 | 不变 |
| 标题 | `titleY = 302` | `296` |
| 文案首行 | `subY = 348` | `330` |
| 字号 / 行距 / 行数 / 可用宽 | `22px / 30 / 3 / 206` | `20px / 25 / 4 / 212` |
| 文案末行 | 348+2×30 = 408 | 330+3×25 = 405 |

4 行末行 405 仍 < 卡框内边 450，安全。带价位（商店卡）那条分支不动（`price` 只出现在可买的卡上，
预告卡永远不传 `price`）。

> **⚠ 这里埋了一个「不改也不会报错」的坑**：`wrapText` 超出行数时会**截断并加「…」**，画面上只是少了几个字，
> 控制台一声不吭。所以要靠单测把「行数 / 行距 / 可用宽」钉住（`tests/shop-preview.test.mjs`），
> 不然下次有人调字号就会静默截断。

## 5. 右手技能框：四行版式 + 往枪口平移

### 5.1 版式

`src/vr/skillHint.js::_draw()` 整个重写成四行（行基线全部来自 `SKILL_HINT`，可热调）：

| 行 | 左 | 右 |
|---|---|---|
| ① | `⚡ <技能名>`（边框色，bold 38px） | `消耗 <N>`（就绪/冷却中=金，积分不足=浅灰） |
| ② | 状态文字（`冷却 N.Ns` / `技能就绪 · 扣左手柄 Grip 释放` / `积分不足 · 现有 N`） | —— 下方是**冷却进度条**（就绪/积分不足也画满，颜色随状态） |
| ③ | `攻击力 <atk>` | `弹道 <N 发/枪｜单发>` |
| ④ | `射速 <fireRate> 发/秒` | `充能 <streak>/<DOTS>`（加速期转金） |
| ④·补 | —— | `加速 N.Ns`（仅加速期；属第 4 行的补充信息，不另起一栏） |

画布 `512×320 → 512×360`（不改画布就会把「加速」那行挤出边框）。

**顺带清掉一处重复**：连杀计数原先在**面板右下角**（`_drawStreak` 里的「杀敌 N/M」）也画一遍，现在
搬到正文第 4 行 ⇒ `_drawStreak()` **只画边框方块**，不再画任何文字（否则两处信息重叠、且和第 4 行/
加速行撞在一起）。边框方块（`edgeDotPositions`）与 `PAD_X = 34` 是**配套**的：正文左右各留 34px，
避开了贴在边框线上、边长 26px 的方块。

### 5.2 「往枪口平移、枪身中间左边」

面板挂在**右手柄 grip** 上（和枪模型同一个父节点），`POSITION` 就是 grip 本地坐标：

- grip 空间里 **-Z = 枪口方向**（`SHOOT.SPAWN_OFFSET` 与 `input.getMuzzle()` 都是沿 grip `-Z` 前移），
  `-X = 玩家左手边`（第五十六修把 `x` 从 `+0.1` 镜像成 `-0.119`，就是在做这个）。
- 所以「枪身左侧 + 往枪口平移」= `x` 保持负、`z` 往负走：`z 0.03 → -0.2`（`y -0.0167 → -0.045`）。

`SKILL_HINT.DEBUG` 同时从 `true` 改成 **`false`**（面板位置已定稿，不再需要面板上那行调试坐标）。
现场若还想微调：把 `DEBUG` 改回 `true`，用左手柄摇杆（前后左右）+ X/Y 键（上下）实时推，
面板上会显示当前坐标，抄进 `userConfig.SKILL_HINT.POSITION` 即可。

## 6. 盾甲兵立绘：3D 摆位永远会「穿」，改成 2D 叠图

**旧做法**（第五十七修）：把「骑士」和「盾牌」两个 GLB 放进**同一个 Group**，调 3D 偏移把盾摆在
骑士左前方（`SHIELD_X/Y/Z/YAW`）再一次性抓帧。现场反馈「盾牌穿模铁甲兵」。

**为什么怎么调都会穿**：抓帧用的是**透视相机**，盾牌只要在 -Z 方向后退就会被骑士遮住、往侧向挪又会
和骑士的肢体相交；而「刚好不穿」这个位置**依赖于模型的实际尺寸与取景半径** —— 换模型 / 调
`PORTRAIT_RADIUS` 就会再穿一次。这是**参数脆弱**，不是调参没调好。

**新做法**（本轮）：**分别抓帧 → 2D 合成**。

```js
// src/game/enemyPortrait.js
const main = await captureOne(renderer, spec.url);            // 骑士：整幅填满的一张正视图
let side = null;
try { side = await captureOne(renderer, spec.shieldModel); }  // 盾牌：另一张，各自整幅填满
catch (err) { /* 盾牌抓不到 → 只画骑士，不阻断整卡 */ }
return composePortrait(main, side);                            // 骑士右上(0.72) + 盾牌左下(0.46)
```

两张图各自的透明背景直接叠 ⇒ **不存在遮挡关系** ⇒ 不可能穿模；`PORTRAIT_MAIN_FRAC` /
`PORTRAIT_SHIELD_FRAC` 只决定「谁大谁小、摆在哪个角」，一眼能读成「骑士在盾后持盾」。

**代价**：盾甲兵这一张从 1 次抓帧变成 **2 次**（其余 5 种精英仍是 1 次）。抓帧本身已经按
`PORTRAIT_STEP_MS = 90` 逐张排队（每张含 2 次 `readRenderTargetPixels` 同步回读），所以整体仍
「进店半秒内逐张换图」，不进关键路径。

> **记一条**：**2D 合成 > 3D 摆位**（当目标只是「一张能认出是谁的图」时）。3D 里要防穿模等于在
> 透视投影下解一个碰撞问题，而 2D 里叠两张透明图是零风险。

## 8. 踩坑

1. **`deepMerge` 是「按 userConfig 覆盖 constants」**：只在 `constants.js` 改了 `SHOP.ITEM_X` /
   `CARD_SCALE_FRONT`，而 `userConfig.SHOP` 里还留着旧值 ⇒ 现场生效的仍是旧值。本轮 `npm test` 唯一
   被改红的一条就是这个（`shop.preview[0].holder.position.x !== -SHOP.ITEM_X`，因为 `userConfig` 把
   `PREVIEW_X` 又顶回 3.0）。**两处一起改**。
2. **删常量要连带改引用点**：`ITEM_Z0` / `PREVIEW_Z0` 被 `_build()`、`_buildPreview()`、`_buildBadges()`
   三处引用，漏一处就是 `undefined` ⇒ `NaN` 坐标（不报错、卡直接消失）。改完 grep 一遍旧键名。
3. **同一行源码两处相同**：`makeCardTexture` 的立绘分支与普通分支各有一条**一模一样**的 `wrapText(...)`，
   按「唯一命中」做定位会被 `hits=2` 拦住 —— 用「从 `if (opts.portrait) {` 到它后面第一个 `} else {`」
   的区间定位，别按键名找。
4. **`_drawStreak` 的重复文字**：把计数搬到第 4 行后，`_drawStreak` 里那段「右下角 …」必须一起删掉
   （只删一半会留下悬空的 `}` ⇒ 语法错误）。
5. **区域牌子与卡的 Z 必须同源**：牌子挂「第一张卡上方」在旧版是对的（起点固定），改成对称排布后
   第一张卡跑到 `-1.725`，牌子要改挂**列中心 `Z=0`**。牌子的高度也必须跟着**该列自己的** `CARD_SCALE_*`
   算（正前方用 `CARD_SCALE_FRONT`、道具列用 `CARD_SCALE_ITEM`）。
