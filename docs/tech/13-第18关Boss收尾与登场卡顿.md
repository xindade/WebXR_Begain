## 2. 收尾：从「回菜单」改成「本局结束」

### 2.1 为什么必须换掉 `toMenu()`

`toMenu()` 的职责是「玩家自己退出 VR → 回到菜单，这一局还能再进」，它调的 `_endRound()`
上报的 `roundOver=false`。而 APK 的退出策略**只对 `roundOver=true` 生效**
（`GameServer.notifyGameEndIfAny`：直播模式下 `cast && !roundOver` 直接 return），
于是旧实现的结果是：**浏览器不收、客户端不回前台、页面停在菜单**，平台下一次「启动游戏」一到
就从第 1 关重开。这正是现场看到的「过一会又回到了第一关」。

### 2.2 收尾时序

| 步骤 | 动作 | 落在哪 |
|---|---|---|
| ① | Boss 代理死亡 → `_win()`：**先清场** → `dispose()` → `waves.cleared = true` | `bossMagician.js` |
| ② | 建 3D 通关横幅（VR 内 DOM 不可见，必须场景内 Sprite） | `winBanner.js` |
| ③ | 横幅到期 → `waves.onWinExit()` → `game._onFinalBossClear()` | `waves.js` / `game.js` |
| ④ | `_closedByPlatformCommand = true`（**不起复活探针**：否则 2s 后封盖被撤、页面又活了 = 没收尾） | `game.js` |
| ⑤ | `_finishRound()`：留痕 `round-clear` → `toMenu()`（内部 `_endRound` = cmd5 + `game-end{roundOver:true}` + 通知 PC 收回放行）→ 退 XR 会话 | `game.js` |
| ⑥ | 直播模式（`?cast=1`）：`cast.dispose()` 停推流 → `location.replace('about:blank')`；APK 收到带 roundOver 的 `game-end` → 顶平台客户端 + 关浏览器 | `game.js` / `MainActivity` |
| ⑦ | 非直播（平台投屏）：进「本局已结束」待机态（黑底 + 一行提示，页面保留、停渲染、继续轮询），等平台下一次「开始」 | `game.js` |

平台侧：`_reportGameEnd(roundOver)` → `POST /api/round/end`（`keepalive`，因为本页马上要消失）→
PC 端 `handleRoundEnd()` 在「本局真的开过（armed）」时发 **CMD 7 结算报文**（`curProgress/maxProgress/score`）
→ 平台弹本局结算。平台之后若再点「结束游戏」，页面已经是 `about:blank`，`closeGame` 落到空处，不影响。

### 2.3 清场：`_clearMinions()`

```js
_clearMinions() {
  this.waves._cancelPendingGroup?.('magicianSub');   // ① 撤掉还没落地的光点（否则收尾后还会冒怪）
  for (const b of this._minions) {                   // ② 移除场上全部召唤物（含 3 只精英）
    if (b && b.alive && this.balloons.list.includes(b)) this.balloons.remove(b);
  }
  this._minions = []; this._refillQueue.length = 0;  // ③ 清补充队列与计数（含「在飞」计数）
  this._pendingRefill = 0; this._pendingElite = 0;
}
```

召唤物的光点因此**必须带分组**：`_spawnMinion()` 里 `opts.group = 'magicianSub'` ——
没有分组就 `_cancelPendingGroup` 不到，收尾后仍会「空降」一只怪（脸谱 Boss 的子实体早有这套，此处对齐）。

## 3. 登场卡顿：把「首帧的一次性开销」提前

### 3.1 根因

`loadGLB()` / `main.js` 的预载只做到 **parse**。GPU 侧两件事仍留到第一次渲染：

1. **纹理上传**：`gl.texImage2D`（PICO 上几 MB 的贴图 = 几十毫秒）；
2. **着色器编译/链接**：three 按 program cache key 首次编译（同样是几十毫秒级，且同步）。

两者都发生在 Boss 模型第一次被画出来的那一帧 —— 也正是「Boss 登场」那一帧。

### 3.2 做法：`warmModelGpu(url)`

```js
// balloonModels.js（需要 _renderer，game.js 构造时已 setRenderer）
export function warmModelGpu(url) {
  if (!_renderer || !url) return Promise.resolve(false);
  return loadGLB(url).then((gltf) => {
    /* 收集 gltf.scene 里所有材质贴图（含 ShaderMaterial 的 uniforms）→ renderer.initTexture(t) */
    /* 再把克隆体塞进临时 Scene，renderer.compile(tmp, new PerspectiveCamera()) */
    return true;
  }).catch(() => false);
}
```

- **不渲染、不回读** —— 成本远低于一次 DepthSprite 抓帧（那种要 12 帧离屏渲染 + `readRenderPixels`）。
- 材质虽是「每个气球各自 clone」，但 shader / defines 相同 ⇒ three 命中同一个 program，
  编译一次就够；纹理本来就在各 clone 之间共享 ⇒ `initTexture` 一次就够。
- 失败静默：预热只是优化，任何一步出错都不影响开怪。

### 3.3 覆盖范围（穿云窗内每帧一项，见 `game._pumpIntroPreload`）

| 关卡 | 预热项 |
|---|---|
| 第 6 关（脸谱） | `FACE_BOSS.MODELS`（蓝/红/黑三张）+ `FACE_BOSS.FAN_MODEL` |
| 第 12 关（龙） | `DRAGON.HEAD_MODEL`（龙身/龙爪用骑士、忍者模型，小怪分支已覆盖） |
| 第 18 关（魔术师） | `MAGICIAN_BOSS.MODEL`（Boss 本体）+ 召唤池敌种（`basic` + 三阶段精英）的 GLB 与 DepthSprite 抓帧 |

> 工程约定：`addUrl(url, warm = true)` 的第三参就是「顺带预热 GPU」；以后新增 Boss 模型，
> 在 `_buildIntroPreloadQueue()` 对应分支加一行带 `true` 即可。

### 3.4 若现场**仍**看到卡顿，按此顺序排查

1. **音频解码**：开场念白（`music/魔术师Boss开头.wav`）首次 `decodeAudioData` 也在关卡开头 ——
   可在进关前先 `fetch` + 解码一次（或让 `_startLevelAudio` 提前一关预热）。
2. **阶段机制首建**：`BossLaserGroup` / `BossGlassWall` / `BossBallWall` 的材质与几何在切换阶段那一帧才建
   —— 可以把构造提前到穿云窗。
3. **召唤物首帧**：`PER_FRAME`（每帧落地几只）调小，或把 `POOL.SPAWN_R` 外的光点飞行时长拉长。

## 5. 验证方法（判据）

1. **清场**：打掉第 18 关 Boss → 场上小兵**瞬间消失**（不再有鬼火/墨汁打过来），横幅出现。
2. **收尾**：横幅 5s 后 —— 头显退出 VR，浏览器被关闭 / 平台客户端回到前台；
   平台界面弹出本局结算（PC 端日志出现 `==ReceiveCall==...,cmd = 7`）。
3. **留痕**：`/api/page/forensics` 里能看到 `round-clear`（`explicit=false`）与 `game-end{roundOver:true}`。
4. **不回归**：平台「启动游戏」→「开始游戏」→ 正常打完一局；下一局仍能从第 1 关正常开始
   （不再出现「回菜单 → 被下一次启动叫回来 → 从第 1 关重开」）。
5. **热调**：把 `WIN_BANNER_SECONDS` 改 0 → 重发内容包 → Boss 一死立即收尾（无横幅）。
