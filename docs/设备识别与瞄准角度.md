# 设备识别与瞄准补偿角度（PICO / Quest / SteamVR）

> **状态：已实现并收敛**（第三十三修实现、**第三十四修固化**，2026-09-24）。本文档同时是设计与使用说明。
> 适用范围：本项目右手枪/子弹的瞄准基准自适应。
> **第三十四修变更**：各槽角度已按上机实测结果**固化进配置表**（Quest = `14 / -14 / 0`）；VR 内「摇杆标定工具」
> 与它落盘的 `localStorage` 历史值（`aim-xyz:<槽>`）**已按需求全部删除** —— 角度只由配置表决定，设备里的旧标定不会再偷偷盖过它。

## 1. 背景：为什么会有一套设备自适应角度

射线和子弹**共用同一条瞄准基准**：手柄 `targetRaySpace` 的本地 `(0,0,-1)` 套上「补偿欧拉角 XYZ」后转世界（见 `input.js` 的 `_aimEulerRad` / `_applyRayAim` / `_rightAim`）。

该角度是按 **PICO 4** 的「`targetRay` 空间 ↔ `gripSpace`（枪模型所挂空间）相对姿态」标定出来的（实测基准 `x = -27°`）。**Quest / SteamVR** 运行时这两个空间的对齐约定不同，于是同一角度整体偏。实测中「射线和子弹一起偏」正说明是**基准问题**（共用一个角），而不是射线、子弹两个独立 bug。

为兼容三套设备，按设备槽各存一份 `{x,y,z}`，自动识别后取对应槽的角。

## 2. 设备识别

### 2.1 四个槽

| 槽名 | 含义 | 备注 |
|---|---|---|
| `pico` | PICO 4 / PICO Neo 系列 | 本机基准设备 |
| `quest` | Meta Quest 系列 | 含 Quest / Quest 2 / 3 / Pro |
| `steamvr` | PCVR 串流手柄 | 含 HTC Vive / Valve Index / WMR（它们共用同一槽，因 SteamVR 下 `targetRay↔grip` 约定一致） |
| `unknown` | 兜底 | 识别不出设备槽时落到这一行 |

### 2.2 识别策略（三级证据，可信度从高到低）

| 级别 | 来源 | 说明 |
|---|---|---|
| ① | **UA 强 PICO 标识** | `PicoBrowser` / `PICO 4` / `Bytedance` / `Pico Neo 3` 等。**没人会伪装成 PICO → 最可信，压过 profiles 与其它 UA**。 |
| ② | `inputSource.profiles` 具体厂商串 | `pico-*` / `meta-quest-*` / `oculus` / `quest-*` / `htc-*` / `vive` / `valve-*` / `index-*` / `wmr` 等。 |
| ③ | 其它 UA 特征兜底 | `OculusBrowser` / `Meta Quest` / `VIVEPORT` 等。 |

关键规则：
- **`generic-*`（如 `generic-trigger-squeeze-thumbstick`）不携带厂商信息**，只能说明「运行时没给厂商信息」。此时**必须放行给 UA 兜底**，不能用 `unknown` 把 UA 短路掉。
- 只有三级都判不出才落 `unknown`。
- 允许「`unknown` → 具体厂牌」**单向升级**（两个手柄先后连时，先到的可能只有 `generic-*`，后到的带来厂牌信息）；已确认过的槽不会因为后到的 `generic-*` 证据降级。

### 2.3 历史坑：PICO 会被误判成 Quest（已修复）

**成因**：PICO 浏览器基于 Chromium，有两类已知行为都会把 PICO 带偏到 `quest` 槽：
1. **伪装成 Quest 的 UA**（UA 里出现 Quest 字样）；
2. **沿用 Meta 控制器 profile** 映射（profiles 报成 `meta-quest-*` / `oculus`）。

**修复思路**（已在 `deviceProfile.js` 落地）：
- ① 级 **UA 强 PICO 标识优先于 profiles**（PICO 一出现即以 PICO 为准，反过来 Meta 伪装 PICO 不存在）；
- ② `familyFromProfiles` 用精确前缀（`^meta-quest` / `^oculus` / `^quest-`，不用 `^meta-`、裸 `quest` 这种过宽泛前缀），宁可判不出交 UA；
- ③ 终极保险 `AIM.DEVICE` 手动锁定（见 2.4）。

### 2.4 手动锁定槽：`AIM.DEVICE`

`userConfig.js` 里的 `AIM.DEVICE` 可以把槽**钉死**，优先级**高于以上全部自动识别**（包括 UA 强标识）。

```js
AIM: {
  DEVICE: null,          // null / 'auto' = 自动识别
  // 识别不准时直接写死：'pico' | 'quest' | 'steamvr' | 'unknown'
  // 例：PICO 上被判成 quest → 改成 'pico'，刷新即生效
}
```

诊断：`getDeviceFamily()` 的最终判定 + `describeDetection()` 会把「原始 profiles / UA 判定 / 是否冲突 / 是否锁定」全摊开，进 VR 时控制台（与页面留痕）会打印一行 `[AIM] 设备槽=… profiles=[…] UA判定=… PICO强标识=…`。

## 3. 手柄瞄准补偿角（三轴 XYZ）

### 3.1 三轴含义（单位：度，作用于手柄本地空间 +X=右 / +Y=上 / -Z=前）

| 轴 | 含义 | 正负方向 | 备注 |
|---|---|---|---|
| `x` | 俯仰 **pitch** | 负 = 射线下压，正 = 上抬 | **主要调这一个** |
| `y` | 偏航 **yaw** | 负 = 射线左偏，正 = 右偏 | 整体左右偏时调 |
| `z` | 翻滚 **roll** | 绕射线自身轴转 | ⚠ **不改变方向**：本地 `(0,0,-1)` 绕 Z 旋转后仍是 `(0,0,-1)`；只改枪管横向姿态，对方向/子弹无影响。只调方向时**保持 0**。 |

### 3.2 当前生效值表

> 实际生效值来自 **`userConfig.js`**（它会在合并时覆盖 `constants.js` 的同名键）。下表为当前工作树状态：

| 设备槽 | x(俯仰) | y(偏航) | z(翻滚) | 来源 / 状态 |
|---|---|---|---|---|
| `pico` | **-27** | 0 | 0 | 实测基准，**勿随意改** |
| `quest` | **14** | **-14** | 0 | **2026-09-24 上机实测固化**（Quest 3，设备 `f38a5e8958ba8f9a`） |
| `steamvr` | -27 | -2 | 0 | 占位值，待实测（含 Vive/Index/WMR） |
| `unknown` | -27 | 0 | 0 | 兜底（识别不出时用） |

> 注：`constants.js` 与 `userConfig.js` 的同名键**现在同值**（都改了），改角度请以 **`userConfig.js`** 为准，
> 否则会出现「改了 `constants.js` 却不生效」的困惑。

### 3.3 取值优先级（单轴）

```
AIM.FORCE（排障强制，可只覆盖部分轴）
  > AIM.BY_DEVICE[设备槽]                     ← 第三十四修起的唯一常态来源
    > SHOOT.RIGHT_PITCH_DEG（仅 x，y/z 取 0）  ← 槽没配 / AIM.ENABLED=false 时的兜底
```

- **第三十四修**：`标定中的实时值` 与 `localStorage 历史标定值（aim-xyz:<槽>）` 两层**已删除** ——
  设备里残留的旧标定值不再生效，固化角不会被偷偷盖过（`tests/aim-profile.test.mjs` 有对应回归）。
- `AIM.ENABLED = false` 时：不走任何设备分支（也跳过 FORCE），恒用 `SHOOT.RIGHT_PITCH_DEG`（回到改造前单一角度行为）。
- 射线与子弹**唯一取值入口**是 `deviceProfile.getAimDeg()`，三处消费（`input.js`）全部经过它，保证两者永不分离：
  - `_aimEulerRad()`（统一把 `{x,y,z}` 转 `Euler('XYZ')`，复用同一 Euler 对象）
  - `_applyRayAim()`（刷到主手红色射线 `ray.rotation`）
  - `_rightAim()`（子弹方向 `outDir.set(0,0,-1).applyEuler(...)`）

### 3.4 长期改角度（推荐做法）

只改 `userConfig.js` 里对应槽的数字，**刷新页面即生效**，不必碰其它文件：

```js
AIM: {
  BY_DEVICE: {
    pico:    { x: -27, y: 0,   z: 0 },
    quest:   { x: 14,  y: -14, z: 0 },   // ← 2026-09-24 Quest 3 上机实测固化值
    steamvr: { x: -27, y: -2,  z: 0 },
    unknown: { x: -27, y: 0,   z: 0 },
  },
}
```

> **生效范围（容易踩）**：`src/core/userConfig.js` 在 PC 端下发清单 `CONFIG_MANIFEST` 里 → 改它**不用重打 APK**，
> PC 端启动/连接时会把新配置推给头显页面；
> 但 `deviceProfile.js` / `input.js`（读角度、消费角度那两层）**不在清单里** → 改这两个文件**必须重新打 APK**。

## 4. 怎么给新设备定角度（VR 内标定工具已移除）

第三十四修按需求删掉了「头显内摇杆标定工具」（热键 / 推角 / 换轴 / 保存 / 复位）与配套的 `localStorage` 存储层。
原因：角度已现场实测收敛（Quest = `14 / -14 / 0`），把工具留在正式包里只会多一个可能被误触的入口，
而且它落盘的旧值会盖过配置表。

### 4.1 现在怎么量一款新设备

1. PC 端与头显都跑起来，进 VR 看**红色射线是否与枪管指向一致**（整体偏 = 该设备槽的基准角不对）；
2. 改 **PC 端那份 `src/core/userConfig.js`** 的 `AIM.BY_DEVICE[对应槽]`，头显页面刷新/重进即生效
   （`userConfig.js` 走 PC 下发，不用重打 APK）；
3. 三轴逐轴试：先调 `x`（俯仰，主要就这一个），再调 `y`（左右偏）；`z` **保持 0**（`z` 不改变方向）；
4. 定稿后把三个数写进仓库的 `userConfig.js` + `constants.js`（两处同值），并登记到 3.2 的表里。

### 4.2 临时对比某个角（不改代码、不重打包）

在 **PC 端那份 `userConfig.js`** 里临时加一层强制值（走 PC 下发，头显刷新即生效）：

```js
AIM: {
  FORCE: { x: -20, y: 3 },   // 可只写部分轴；对比完删掉这一行即恢复
}
```

`AIM.FORCE` 优先级最高（高于 `BY_DEVICE`），删掉即回到配置表。

### 4.3 标定工具的算法（移除前的实现要点，备查）

- 角度语义：`Euler(x, y, z, 'XYZ')` 作用于手柄 `targetRay` 本地 `(0,0,-1)`；`x`=俯仰、`y`=偏航、`z`=翻滚（不改变方向）。
- 推摇杆：前推 `+1°`、后拉 `-1°`（步长 `CALIBRATE.STEP_DEG`），长推按 `REPEAT_MS`(120ms) 连续步进。
- 左右换轴：X 俯仰 → Y 偏航 → Z 翻滚，带回差防误触。
- 保存 = 写 `localStorage['aim-xyz:' + 设备槽]`；复位 = 删掉该键、回到 `BY_DEVICE`。
- 热键 = 左手摇杆按下连按 3 次（间隔 < 0.6s）；开启期间左手摇杆被占用，转向暂停。

> 若确需重做，按上面要点重写即可；或直接走 4.1 / 4.2 的「改 PC 下发配置」路线，完全不用写代码。

## 5. 排障速查

| 现象 | 根因 / 处理 |
|---|---|
| **PICO 被判成 Quest** | 改 `AIM.DEVICE = 'pico'` 钉死（典型：PICO 浏览器伪装 Quest UA / 沿用 Meta profile）。进 VR 看 `[AIM]` 日志确认槽。 |
| 换了新头显，射线/子弹整体偏 | 该设备槽还是占位值 → 按第 4 节量一遍，把实测值写进 `userConfig.AIM.BY_DEVICE[槽]`。 |
| Quest 上射线/子弹仍整体偏 | 先看 `[AIM]` 日志里槽判对没有（被 PICO 的 profile 带跑就 `AIM.DEVICE='quest'`）；槽对 → 按第 4 节重量角度。 |
| 改了 `constants.js` 的角度不生效 | 改 **`userConfig.js`** 的 `AIM.BY_DEVICE`——它被合并覆盖，`constants.js` 的同名键会被忽略。 |
| 只调方向却怎么调都没反应 | 检查是不是在动 `z`（roll）——`z` 不改变方向，只调方向请保持 `z=0`，改 `x`/`y`。 |
| 改了角度、头显上没变化 | 改的是 `deviceProfile.js` / `input.js`？它们在 APK 里，必须**重打 APK**；只改 `userConfig.js` 才会随 PC 下发即时生效。 |
| 想临时强制一个角做对比 | `AIM.FORCE = { x: -20 }` / `{ x: -20, y: 3 }`（可只写部分轴），刷新生效，不落盘。 |
| 想回到改造前行为 | `AIM.ENABLED = false`（恒用 `SHOOT.RIGHT_PITCH_DEG` 单角）。 |
